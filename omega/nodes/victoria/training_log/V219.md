## Hypothesis

This is **infrastructure, not strategy** — one deliberately-scoped bet: make the
eval reproducible from committed state. V218 and the strategic audit converged on
the same blocker (audit R1, the precondition for every other recommendation):

- The committed `data/macro_cache.db` is **all `__failed__`/0.0** for every macro
  series (VIX, DGS2, DGS10, dollar index) → every backtest in the V207→V217 arc
  ran with **macro=0** (VIX/yields/dollar all inert).
- V217's celebrated "first 6/6 byte-identical hermetic eval" was real **within a
  session** but **not reproducible across sessions**: it rode an uncommitted
  `macro_cache.db` stub + a session-specific funding cache. A committed-state no-op
  control (V218.B) diverged from V217's logged numbers by >$6K / 16 trades
  (`V218-matrix.md:188`).

V219 freezes + commits the data caches with health tripwires so that a clean
checkout reproduces the eval byte-for-byte. **No strategy change.** IC wiring
(audit R2) and distributional eval (audit R3) are V220+ — separate bets.

There is no gate to "beat" here. The success criterion is reproducibility:
6/6 determinism still holds at sleep=10 with the repaired+committed caches, and
the tripwires fire when the substrate is corrupted.

### Macro cache repair — data provenance

FRED is the canonical source but is **broken from this environment**: `DEMO_KEY`
returns **HTTP 400** and no `FRED_API_KEY` is set, so all 4 series sentinel-failed
to `__failed__`/0.0 (that is exactly how the inert state arose). Stooq is behind a
JS proof-of-work wall (unusable headless). **Yahoo Finance works**, so V219 sources
real, current values from Yahoo (through 2026-06-09/10):

| FRED series | Meaning                  | Yahoo source        | Exact / proxy | Latest value |
|-------------|--------------------------|---------------------|---------------|-------------:|
| `VIXCLS`    | CBOE VIX                 | `^VIX`              | **exact**     | ~19.9        |
| `DGS10`     | 10Y Treasury CMT yield   | `^TNX`              | **exact** (%) | ~4.53        |
| `DGS2`      | 2Y Treasury CMT yield    | `2YY=F` (CME fut.)  | close proxy   | ~3.84        |
| `DTWEXBGS`  | Fed broad $ index (26cy) | `DX-Y.NYB` (ICE DXY)| **level proxy** | ~99.9      |

- **`DGS2` ← `2YY=F`**: the CME 2-Year Yield future tracks the 2Y CMT closely
  (3.84 vs an interpolated 3mo/5yr curve estimate of ~3.86). Percent-scale, so the
  2s10s slope (4.53 − 3.84 = +0.69) is correct.
- **`DTWEXBGS` ← `DX-Y.NYB`**: ICE DXY is a *narrow* 6-currency index at a different
  base level (~100) than the Fed broad index (~120). This is immaterial: the only
  consumer, `dxy_signal.py`, uses **5-day returns + BTC correlation**, never the
  absolute level — so the proxy's *return dynamics* are what feed the signal, and
  those are directionally faithful. Documented proxy, not a silent substitution.

**VIXCLS is repaired but inert.** `VIXSignal` (`vix_signal.py`) reads `^VIX` via
`yfinance` **directly**, not the macro cache — so in frozen mode the V215 HTTP guard
blocks it and VIX stubs to the 20.0 neutral baseline regardless of the cached value.
Repairing VIXCLS keeps the cache/manifest complete and unblocks a future rewire, but
**wiring `VIXSignal` to read the cache is a V220+ item** (queued in
`OBSERVABILITY-BACKLOG.md`). The two macro series that actually reach the composite
today are `DTWEXBGS` (dxy) and `DGS2`/`DGS10` (yield_curve).

### Frozen-mode read anchor (the substrate fix the repair requires)

`MacroDataCache._read_macro` computes its cutoff as `now() - lookback_days`. While
every series was `__failed__` this returned `[]` regardless of `now()`, so the
wall-clock dependence was **dormant** — which is *why* V216/V217 hit 6/6 hermetic
without touching it. Populating real rows reactivates it, with two failure modes:

1. **Silent expiry.** Data ends 2026-06-09; as `now()` slides past `latest −
   lookback`, dxy (`window+10` ≈ 30–40d) empties first, yield_curve (90d) follows —
   so within ~a month the committed DB **reverts to the inert state V219 exists to
   kill**, invisibly.
2. **False-PASS determinism.** Same-day N=2 replicates share `now()` → identical
   macro → $0.00 spread, "passing" without proving the cross-session reproducibility
   that is the entire V219 mandate.

**Fix (gated on `OMEGA_FROZEN_CACHE=1`, live path unchanged):** anchor the cutoff to
the cache's own `MAX(date)` for the series instead of `now()`. The read becomes a
pure function of committed bytes — deterministic across sessions, never expires. This
is substrate (part of the freeze), pre-registered here, not strategy.

### Determinism verdict — falsifier #1 fired (partial): 3/4 hermetic, trend_OFF FAILs

Three of four cells are byte-reproducible from committed state at sleep=10
(crisis_OFF $0.00, trend_ON $0.85, recent_OFF $6.52 — all ≪ $200 floor). **trend_OFF
FAILs at $596.91** (27 vs 26 trades). Pre-registered falsifier #1 fired; bisected
with `scripts/per_field_diff.py` on the two replicates:

- **First and only divergent field: cycle 3, `basic_signals.value`, |Δ| = 3.2e-18**
  — a *sign flip in the sub-ulp bits around zero* (r1 −2.67e-18 vs r2 +5.34e-19).
  Cycles where `basic_signals.value` is cleanly non-zero are byte-identical; only the
  near-zero cycles split (147/198 cycles from 3). Same *field* and magnitude as the V217
  channel, but a **distinct residual order-channel**: the V217 channel was Apple vecLib
  BLAS parallel-reduction order, and the BLAS pin is verified active+effective here
  (`run_training.py:55-64` sets all 5 thread vars to 1 + re-execs; gated on
  `--frozen-cache`, which is in argv). So this is a *second* summation-order source in
  `basic_signals` that the BLAS pin does not cover — latent while macro=0, surfaced by
  real macro.
- **It is NOT a data / cache / WAL channel.** `_macro_bias_score` is byte-identical
  (0.1781) in both replicates, as are all 34 other fields — the repaired+committed
  macro is read reproducibly; the substrate freeze itself is sound (falsifier #3
  effectively holds: macro inputs stable across replicates). The channel is purely
  the order of summation of the `basic_signals` composite.
- **Why it re-opened.** V217 reached 6/6 hermetic *with macro = 0*, which zeroed the
  order-sensitive terms in the composite (0 + 0 + … = 0 regardless of order). V219's
  whole point — populating real macro (dxy, yield_curve) — re-introduced non-zero
  terms whose low-order bits are summation-order-sensitive. The macro repair did not
  *introduce* a channel; it **un-masked the latent V217 one**.
- **Why only trend_OFF.** The sub-ulp noise reaches a trade only where a conviction
  sits exactly on a decision boundary. **recent_OFF demonstrates this directly:** its
  spread is $6.52 with an *identical 22/22 trade count* — the same near-zero noise is
  present but crosses no boundary, so it stays a PASS. trend_OFF is the one boundary-
  adjacent cell, where the identical noise flips a single trade (27↔26 → $597). So the
  $597 is not a larger/different channel — it is the recent_OFF noise crossing a trade
  boundary. (The boundary-sensitive cell shifted from V216-era's recent-OFF / crisis-ON
  because real macro moved the convictions.)
- **Why BLAS-pinning + PYTHONHASHSEED don't catch it.** BLAS=1 fixes parallel-reduction
  order; PYTHONHASHSEED=42 fixes str/bytes/datetime hashing. Neither fixes **`id()`-
  ordered iteration** of non-string objects (sets/dicts keyed on objects), whose order
  is ASLR-randomized per process — precisely the channel `check_determinism.sh`'s
  header flags separate processes for exposing. Strong-inference root: an `id()`-ordered
  accumulation in the `basic_signals` composite path. (Exact site is a V220 bisect — the
  per-field tool names the *field*, not yet the *line*.)
