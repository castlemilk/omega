# V260 — News-driven regime detection (Track F) — LLM-vs-calendar agreement probe

**Date:** 2026-07-14 · **Author:** claude (Opus 4.8) · **Type:** Phase-0 offline probe (pre-build gate)
**Parent scope:** [`V254_ALT_DATA_SCOPING.md`](V254_ALT_DATA_SCOPING.md) Track F (news-regime detector) ·
**Distinct from:** [`V245`](README.md) (gdelt daily-aggregate as a *trading signal* — REFUTED). V260 tests
the **same frozen gdelt series in a different role: as a REGIME DETECTOR**, not a composite signal.
**Code touched (this pre-reg):** offline scorer only — `omega/tools/v260_news_regime_scorer.py` (new,
scorer infra, allowed by mandate). **No strategy/signal/features/reasoning_layer edit. No flag.**
**Budget cap:** ≤ $10 agy spend (`gemini-3.1-pro-low`), ~32 calls expected.

## Hypothesis

Finer-grained news + LLM extraction of regime-relevant events *might* produce a **different**
regime classifier than the algorithmic calendar classifier (`walk_forward_freeze.py::regime_label`,
which is a pure **price-metric** function: `crisis` if max_dd≥0.30 or basket_ret≤−0.15, `trend` if
basket_ret≥0.20, else `recent`). If an LLM reading only **news tone/volume** reproduces the
price-derived labels, news carries no independent regime information. If it diverges *coherently*,
there may be a news-regime axis orthogonal to the price-metric axis.

## Design (pre-registered, no post-hoc tuning)

**Comparison unit = the walk-forward window** (32 windows in `data/walk_forward_manifest.json`, each
already carrying a calendar `regime ∈ {crisis, trend, recent}` and a `high_vol` flag). The calendar
labels exist **only at window granularity** (they are computed per-window from price metrics), so the
LLM must classify at the same granularity — a per-*day* label would have no calendar counterpart to
compare against. This is a deliberate reconciliation of the Track-F "classify each day" sketch with
the fact that the ground-truth labels are per-window.

- **Input per window:** the 5 gdelt categories × {tone, vol} = 10 frozen daily series
  (`gdelt_{tone,vol}_{central_bank,crypto_regulation,financial_crisis,geopolitical,sanctions}`),
  sliced to the window's `date_range`, summarised to per-category {mean, min, max, last, n_spikes}
  tone + mean/max vol. Deterministic, no look-ahead beyond the window.
- **LLM task:** classify the window's dominant news regime as **exactly one of
  {panic, uncertainty, calm, euphoria}**. Respond JSON `{regime, confidence, reasoning}`.
- **Model:** `gemini-3.1-pro-low` via `agy` (same binary/cache namespace as V241/V258).
- **Hermetic cache:** each response cached at `data/frozen_llm_cache/v260/{prompt_hash}.json`
  (`prompt_hash = sha256(canonical_prompt_json)[:16]`), so re-runs are $0 and deterministic.
- **Mapping (pre-declared):** `panic→crisis`, `euphoria→trend`, `calm→recent`, `uncertainty→recent`
  (uncertainty is the ambiguous/neutral bucket that maps to the residual `recent` regime). The full
  4×3 confusion matrix is reported regardless, so an alternative mapping can be read off post-hoc
  **for color only** — the falsifier is judged on the pre-declared mapping.

## Falsifier (pre-registered)

- **Agreement > 95%** (LLM-mapped label == calendar label on >95% of windows) → **REFUTED**: the LLM
  is just re-deriving the price labels from news; no new information, a re-labeling.
- **Agreement < 20%** → **REFUTED**: no coherent signal; the LLM's news-regime is noise w.r.t. the
  regime structure.
- **20% ≤ agreement ≤ 95%** → **"signal exists"** — a news-regime axis that is neither redundant with
  nor noise against the calendar axis. **Cap: FLAG-GATED.** Even a coherent-but-different classifier
  cannot be shown to *help trading* without a full V###+1 grid (news-regime-conditioned entry/sizing),
  which is **out of scope** for this Phase-0 probe. V260 reports the finding; it does not ship a flag.

## Integrity guards

- No live-broker. No strategy/signal/features/reasoning_layer edits. No flag added.
- Scorer is read-only against frozen series + manifest; writes only its cache + a results JSON.
- ≤ $10 agy spend; if the run would exceed ~50 calls or the budget, checkpoint and stop.
- Anti-Goodhart: the mapping and the 3-band falsifier are declared **here, before the run**. No
  re-mapping to manufacture a pass; the confusion matrix is published either way.

## Results

Run: 2026-07-14, `gemini-3.1-pro-low`, 32 windows, 32 agy calls (all cache misses;
re-runs now $0). Cost well under the $10 cap (~32 × ~1.5KB prompt + tiny output).
Artifact: `data/v260_news_regime_scorer.json`.

| Metric | Value |
|---|---|
| Windows scored | 32 / 32 |
| agy calls (cache misses) | 32 |
| Agreement (pre-declared mapping) | **0.25** (8 / 32) |
| LLM label distribution | **uncertainty ×30, panic ×2** (calm ×0, euphoria ×0) |
| Calendar distribution | crisis ×12, trend ×10, recent ×10 |

### The 0.25 is a degeneracy artifact, not signal — information-theoretic diagnostic

The pre-registered 3-band falsifier assumed a **non-degenerate** 4-way classifier. The
LLM instead collapsed to a **near-constant output**:

| Diagnostic | Value | Reading |
|---|---|---|
| LLM label entropy H(LLM) | **0.34 bits** (of 2.0 max) | near-constant classifier |
| Majority-class share | **93.8%** (30/32 "uncertainty") | one label dominates |
| Labels actually used | **2 of 4** (calm, euphoria never emitted) | half the class space is dead |
| Mutual information MI(LLM; calendar) | **0.11 bits** | vs a 1.58-bit target |
| Normalized MI (MI / H(calendar)) | **0.07** (7%) | ~zero shared information |
| The 2 non-majority calls ("panic") | both land on `recent` windows | wrong-direction (panic maps to crisis) |

Confusion (LLM × calendar): `uncertainty → {crisis:12, trend:10, recent:8}`,
`panic → {recent:2}`. The 8 "agreements" are **entirely** the mapping accident
`uncertainty→recent` intersecting the 10 recent windows (minus the 2 that flipped to
panic). A classifier that emits one label 94% of the time has **~zero mutual
information** with the calendar labels — this is the strongest possible form of the
pre-registered "<20% — no coherent signal" failure, even though the raw agreement
number lands inside the 20–95% band. (Same discipline as V258: a numeric clause can
pass while a structural clause fires; the structural read wins.)

## Verdict: **REFUTED** — LLM news-regime detector is a degenerate (constant) classifier.

Given only the 90-day aggregated GDELT tone/volume summary, `gemini-3.1-pro-low`
cannot discriminate regimes — it defaults to "uncertainty" for 30 of 32 windows and
never once emits "calm" or "euphoria". It carries **0.11 bits** about a 1.58-bit
target (7% normalized MI). There is **no coherent news-regime axis** recoverable from
the daily-aggregate GDELT series at window granularity by this method. This is the
V245 lesson in a new role: the **daily-aggregate GDELT series lacks the resolution**
to support a regime classifier, just as V245 found it lacked the resolution to support
a trading signal. The mechanism (news → regime) is not refuted in general; **this
input granularity** (5-category daily tone/vol aggregate) is too coarse for an LLM to
extract regime structure from.

**No flag was on the table** (Phase-0 probe), so nothing ships. Root-cause class:
**R2/R5 hybrid** — the signal, if any, is below the resolution of the aggregate input
(R2), and the daily-aggregate collapse destroyed regime-discriminating detail before
the LLM saw it (R5), echoing V258's input-starvation and V245's aggregate-resolution
death.

### Reopen criteria (not pursued here)

A finer input might change the result: per-*event* GDELT extraction (headline-level,
not daily category means), a shorter classification window (weekly, more windows), or
adding price-free but higher-resolution features (e.g. options-implied vol term
structure). All require new data-freeze work and a fresh pre-registration — out of
scope for this offline probe. Until then, news-as-regime-detector is **REFUTED at the
available (daily-aggregate) granularity**.
