## Hypothesis

**The third channel is a full-precision floating-point reduction whose summation
order is non-deterministic across processes** — the same class as the V211
basket_std / basket_mean fix, but in whichever signal field the per-field hash names.
Because `PYTHONHASHSEED=42` is pinned, this is **NOT** ordinary str-keyed `dict`/`set`
iteration (that is already deterministic at a fixed seed). The surviving cross-process
sub-12th-bit drift is textbook **float non-associativity over an `id()`-ordered
collection** — a `set`/`dict` of *objects* (identity hash, memory-address-ordered,
not seed-controlled), or a numpy/array reduction whose build order varies by process
memory layout. Threaded through the composite, the last-bit drift only changes a
**trade decision** where a conviction sits within ~$1k of an entry threshold — which
is exactly why **crisis-ON** and **recent-OFF** fail while their opposite arms and
trend (post-fence) do not: only those cells carry a borderline trade near the flip.

**Two-step plan (observability first, then fix):**

1. **Ship the per-field full-precision fingerprint** (the cheapest lever). The current
   `signal_fingerprint.jsonl` *proves* divergence (`fp` diverges) but the dump rounds
   every value to 12 places, so `fingerprint_diff.py` hits the dead-end
   `(fp differs but no scalar value differs)`. A per-field IEEE-754-bit-exact hex hash
   makes the next bisect **one command**: it names the `(cycle, signal_name)` whose
   bits drift. **This tool is guaranteed to localize** — `fp` is a pure function of
   exactly those per-field values (`!r` round-trips bit-exact), so if `fp` differs
   while key-sets match, at least one field's IEEE bits differ by construction. The
   per-field diff *cannot* reproduce the V216 dead-end.

2. **Localize + close the channel.** Bisect V216's failing cells (recent-OFF, crisis-
   ON) with the per-field tool → name the field → trace *its* computation → apply a
   `sorted(..., key=<value-stable>)` canonical order at the order-dependent reduction
   (V211 method), OR, if the named field's computation has no order-dependent
   reduction, describe and fix the actual resolution-sensitive source (do **not** force
   a sort that merely *looks* load-bearing — the V213 trap).

### Note: brief said "(ticker, signal_name)"; the data is market-level

The task brief specified a per-`(ticker, signal_name)` artifact. The diverging `fp` is
over the **market-level `last_signals` dict** (btc_dominance, vrp, carry, … + `_*`

localize.

## Methodology lesson (pre-registered, to codify in the skill)

If V217 closes the named field and a *new* field immediately appears at the next gate
run — and this keeps happening one field at a time — we have a **serial channel-chase
pattern**, not a finite set of parallel channels. The codification: **determinism
fences must be validated at BOTH selector ON and OFF, not just ON** (V216 validated the
sizing fence only on the trend gate where both arms happened to pass, and the audit
later revealed two *other* cells still failing). The per-field tool makes each chase
step one command, but if the chase does not terminate after this step, the skill's
reflection section must add: *"a determinism fix is not 'done' until the full 6-cell
{3 gates × ON/OFF} grid is byte-identical — a single passing gate is not sufficient
evidence."*

### Step 4 — per-field bisect (the channel) — DONE

**The channel is multi-threaded Apple Accelerate (vecLib) BLAS/LAPACK
non-determinism.** Localization path:

1. **Per-field tool named the field in one command.** Canonical recent-OFF N=2 at
   sleep=10 reproduced the FAIL ($400.42 spread); `per_field_diff.py` on the fresh
   per-field artifacts:
   ```
   *** FIRST DIVERGENT FIELD: cycle 6, signal 'basic_signals.value' ***
     A.value_hex = bc60000000000000  (-6.938893903907228e-18)
     B.value_hex = bc389d89d89d89d9  (-1.3344026738283132e-18)   |Δ| = 5.6e-18
   ```
   The value is floating-point **noise around zero** (~1e-18) — a signed sum that
   nets to ~0, where the residual depends entirely on summation order.
   One bash invocation:
   `python3 scripts/per_field_diff.py data/<A>_per_field_fingerprint.jsonl data/<B>_per_field_fingerprint.jsonl`

2. **Full-sweep across all 200 cycles** named four divergent fields:
   `rmt_signal.value` (41 cy), `_basic_signal_consensus` (41), `_basic_signal_divergence`
   (41), `basic_signals.value` (7). `rmt_signal` is in warmup (returns 0.0) until cycle
   30 yet `basic_signals` diverges at cycle 6 → **independent roots**, sharing a deeper
   cause.

3. **Cheap-reproduction unlock.** The earlier sleep=0/cycles=3 probes were *identical*
   only because they never reached cycle 6 — not because of sleep. At **cycles=40,
   sleep=0** the divergence reproduces (cycle 6, basic_signals.value), turning the bisect
   into a ~4-min loop. So the channel is **NOT sleep-coupled** (the V213-lesson trap was
   avoided — but the acceptance gate still runs at sleep=10).

4. **Root identified by A/B.** numpy here is Apple **Accelerate** (vecLib), multi-threaded
   via GCD. Re-running the cheap repro with BLAS pinned to 1 thread
   (`OMP/OPENBLAS/MKL/NUMEXPR/VECLIB_*_THREADS=1`) → signal layer **bit-identical**;
   unset → diverges at cycle 6. The Python-level reduction order was already deterministic
   (`market_data.items()`, `SIGNAL_NAMES`); the non-determinism is the **parallel
   reduction order inside BLAS** (`np.corrcoef`, `eigvalsh`, matmul). This is the
   pre-registered hypothesis's *numpy-reduction* branch — NOT a Python `sorted()` issue.

### Step 5 — fix applied

Pin BLAS to a single thread in frozen-backtest mode. The thread-count env vars must be
present **before numpy/BLAS dylib load**, so the fix piggybacks on the existing
`PYTHONHASHSEED` self-re-exec in `run_training.py` (lines 32–66): set the 5 vars (gated on
the `--frozen-cache`/`--backtest-snapshot` flags), re-exec once so they are in place at the
true process start. Live trading uses a different entry point (`pipeline_server`) and is
gated out → live path byte-unchanged.

**Validated on the actual shipping path** (advisor catch: the A/B above used a *shell
`export`*, but the fix sets `os.environ` in-process; for Accelerate `VECLIB_MAXIMUM_THREADS`
may be read at dylib load): re-ran cycles=40 sleep=0 N=2 with **no shell export**, relying
solely on the in-process set + re-exec → **bit-identical**. The re-exec lands the vars
before numpy loads.

**Numeric-baseline note:** single-threaded BLAS produces *different* floating-point values
than multi-threaded everywhere (different reduction order), so all six cells get new
numbers vs V216 — a new hermetic baseline. The selector ON−OFF Δ stays valid because both
arms share the pin.
