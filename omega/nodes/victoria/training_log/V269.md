### 2.4 A2 — `bookTicker` is depth-1, and cannot answer R4's headline question

Verified schema from a real file
(`NEARUSDT-bookTicker-2023-10-15.csv`, 958,819 rows, 12.2 MB zip → 86 MB CSV):

```
update_id,best_bid_price,best_bid_qty,best_ask_price,best_ask_qty,transaction_time,event_time
```

This is **top-of-book only**. It carries the best bid/ask and the size resting *at*
those two prices. It contains **no ladder**, so it cannot be walked to $200k or $2M.

R4's headline deliverable was `Sharpe(2k → 2M)`. Producing that from depth-1 data
requires extrapolating a book shape beyond the touch — i.e. assuming the very
coefficient V267 refused to assume. **The historical L2 lane is therefore
data-blocked at the source, not merely unfetched:** Binance publishes no free
historical L2 ladder for USDⓈ-M perps. Only the forward `/fapi/v1/depth` collector
(Phase B) yields true L2, and it accrues **one day per day** — the same calendar
constraint that killed V268.

What depth-1 *can* honestly measure: the **realized quoted spread** and the
**top-of-book resting size** at the timestamps the strategy traded. That speaks
directly to V267's G2 result (`slippage_to_median_zero_bps = 1.6475`) — is the real
half-spread above or below the 1.65 bps the edge can absorb? That is falsifiable and
is *not* an impact curve.

## 5. Gates (apply to whichever option is authorised)

- **G-S (storage)** — abort before any write if projected retained bytes + 20%
  headroom exceed free disk. Re-checked before every symbol.
- **G-D (determinism)** — re-running any landed partition is byte-identical:
  gzip `mtime=0`, rows sorted by `(transaction_time, update_id)`, provenance string
  computed from **retained** row counts, never from fetched-archive counts or any
  wall-clock value (the V262 defect).
- **G-P (structure)** — `_assert_symbol_matches_partition()`, strictly monotonic
  timestamps, no cross-month/day spill.
- **G-R (rowcount falsifier)** — landed rows must be within **±5%** of the source
  archive's row count for that symbol-day; a larger gap is flagged an **R4 data
  defect**, not silently accepted.
- **G-C (coverage honesty)** — the verdict must restate the 12.6% join rate and the
  0% `high_vol` coverage wherever a spread number is reported.
