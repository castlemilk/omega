## Track C — recent determinism channel (precondition): CLOSED

### Diagnosis (named field)

Bisected V226's recent-OFF replicates with the existing tools (no re-run needed —
the V214/V217 fingerprint artifacts survived in `data/`):

- `per_field_diff.py` on `v226_skew_off_recent_r{1,2}_per_field_fingerprint.jsonl`
  → **FIRST DIVERGENT FIELD: cycle 22, `basic_signals.value`** (A=9.34e-19 vs
  B=−2.00e-19, |Δ|=1.13e-18 — a near-zero canary), split in 12/179 cycles.
- `signal_contribs.jsonl` (the per-trade `signal_traces`, which the post-demean
  aggregate fingerprint is blind to) named the real channel: **cycle-83 NEARUSDT
  had `spy_signal=-0.1833` in its composite in r1 but the signal was ABSENT in
  r2** — a per-ticker *signal presence flap*, not a sub-ulp wobble. Composite
  0.194 vs 0.281, conviction 0.95 vs 1.53 → entry cycle 95↔93 → $1,621.99 spread.

### Root cause

`SPYSignal.compute` (and its dormant sibling `VIXSignal.compute`) fetch live data
via **yfinance 1.3.0, which uses curl_cffi/requests — NOT urllib**. The V215
frozen-cache HTTP guard patches `urllib.request.OpenerDirector.open` and its own
comment asserted "urllib is the only HTTP mechanism in the Victoria layer." That
was **false**: the urllib leak-log recorded **zero** yahoo hosts across 2,000+
blocked calls, yet `_HAS_YFINANCE=True`. So in a frozen backtest SPY/VIX silently
hit live Yahoo and returned wall-clock-dependent data; same-seed replicates run
~40 min apart got different SPY momentum → the presence flap.

### Fence

curl_cffi can't be patched the way urllib was, so the fix is a per-signal freeze
fence at the top of `compute()`:

```python
if os.environ.get("OMEGA_FROZEN_CACHE") == "1":
    return 0.0
```

Applied to **both** `signals/spy_signal.py` and `signals/vix_signal.py` (sibling
named, not left dormant). Live trading (flag unset) is byte-unchanged.

### Observability shipped (the V226-surfaced hook)

`scripts/check_frozen_http_fence.py` — an AST preflight (mirrors
`check_no_wallclock.py`) that FAILs if any `signals/*.py` imports a non-urllib HTTP
client (`yfinance`/`requests`/`httpx`/`curl_cffi`/`aiohttp`) without an
`OMEGA_FROZEN_CACHE` fence. Wired into `check_determinism.sh` as a preflight gate,
so this regression class can never silently return. `tests/test_frozen_http_fence.py`
(4 tests) pins the fence behaviour.

## Track B — drawdown-magnitude gate (the shipped win)

### Hypothesis

V226's fork #3 said the gate's *semantics* were wrong, not the signal: the
1-cycle-lagged VRP→regime label calls ~half of every benign window
{crisis,high_vol}. **Bet:** add a second AND condition — fire only when the
per-ticker **realized recent drawdown** (last `_DD_LOOKBACK=5` daily bars,
`1 − close[-1]/max(close[-5:])`) exceeds threshold X — and the gate becomes a real
crash selector. Calibrate X so `skew_on_cycles < 40` on trend/recent; if the
concentrated firing then makes **crisis Δ > +$200 with trend/recent within ±$200**,
the realized proxy works after all.

### Changes

- `features.py` — new `crisis_skew_drawdown_threshold: float = 0.0` (0.0 ⇒ V226
  regime-only behaviour, byte-reachable).
- `signal_generation.py` — `_realized_drawdown_mag()` pure helper (max + one
  divide, no accumulation); `_regime_gated_skew()` gains `drawdown_mag` +
  `dd_threshold` params (extra boolean branch; the term fires only if
  `drawdown_mag ≥ dd_threshold`). Calibration sink: per-cycle gate decision +
