## §2 — Refuted: the `dag_pipeline.py` concurrency pivot (dead code in the eval)

The prior attempt pivoted to "the real channel is `omega/core/dag_pipeline.py`'s
`ThreadPoolExecutor + as_completed`; signal completion order is non-deterministic."
**This is refuted by primary-source evidence — the DAG path never runs in the eval:**

1. `_do_compute_signals_dag` (the only caller of `DAGPipeline`) is gated at
   `victoria_node.py:927`: `if os.getenv("DAG_PARALLEL"): return self._do_compute_signals_dag(inp)`.
2. **`DAG_PARALLEL` is never set anywhere** — not in `run_training.py`, not in
   `scripts/check_determinism.sh`, not in any Makefile/yaml/.env, and not in the
   live shell (`echo $DAG_PARALLEL` → unset). A repo-wide grep finds only *reads*,
   never an assignment. The serial path `_do_compute_signals` is what runs.
3. There is **no `ThreadPoolExecutor` / `as_completed` / `asyncio.gather` anywhere
   in `omega/nodes/victoria/` or `omega/eval/`** — the serial eval path has zero
   in-process concurrency. WS feed threads are additionally stubbed out in backtest
   mode (`run_training.py:506`, `_WS_FLAGS` disabled).
4. **The gate proves it for free:** `check_determinism.sh` does not set
   `DAG_PARALLEL` either, so if the break reproduces under the gate (§ Falsifiers),
   the DAG was dead by construction during the failing runs — empirical, not just
   static.
5. Even *if* the DAG ran, the prior attempt's "preferred" fix (collect-then-sort
   the `as_completed` results) is a **no-op**: `dag_pipeline.py:223` does
   `accumulated[name] = result`, keyed by node name — completion order cannot
   change the resulting dict. Only `max_workers=1` would serialize, and only if the
   node `fn`s shared mutable state. The preferred fix was doubly wrong.

**Decision: `dag_pipeline.py` is NOT modified in V214.** Canonical-ordering dead
code would imply the channel was found when it was not, and would muddy the V214
narrative. This is the *inverse* of the V207b error the prior attempt itself
flagged — a "subsystem-OPEN claim without checking the runtime gate (env flag)."
Queued to `OBSERVABILITY-BACKLOG.md`.

## §3 — Hypothesis (corrected): a wall-clock read feeds a signal value; channel is UNKNOWN but bisectable

Per V213.md's own relocalization (§Next-steps): the channel is a **wall-clock /
clock-read dependency feeding a signal value**, not thread scheduling. The evidence
shape favors a clock read over async jitter:

- **Bimodal** outcome (81↔83 trades) — consistent with runs occasionally crossing a
  discrete hour/day boundary, not the smooth spread thread races produce.
- The recent-PnL level shift (~−$2,900 sleep10→sleep0) is **deterministic** — a
  consistent level shift is a clock read, not thread jitter.
- Activates between sleep=3 and sleep=10 (longer wall-clock spans more boundaries).
- **Survives `--frozen-cache` + per-run DB-state isolation** — an in-process clock
  read is invisible to every hermeticity guard.

**Candidate channels (NOT asserted — to be discriminated by the fingerprint):**
(a) a time-decay / data-age signal computing `now − data_ts` with wall-clock `now`;
(b) the geo `datetime.now(UTC)` at `signal_generation.py:732` *if* not actually
disabled in backtest (the §1 "dead path" claim is re-verified by the fingerprint);
(c) a 15-min cache-TTL `now = time.time()` boundary crossing mid-run;
(d) fallback only: a background thread surviving `time.sleep` (V213 step-3 fallback).

**The V214 method is instrument-then-localize, not assert-then-patch.** Ship the
per-cycle signal-values fingerprint (§ Observability #4) + mode-switch trace (#3),
run two byte-identical-input replicates at the canonical **sleep=10**, and diff the
fingerprints to find the **first cycle** where signal values diverge and **which
signal** moved. That signal is the channel. Only then is a fix (thread bar-time
through, never wall-clock in replay) written — in V214 if cheap, else V215.

## Conclusion

**Channel LOCALIZED (confirmation deferred to V215's fix+re-gate). The determinism
break is not a code-ordering bug — it is a hole in `--frozen-cache`.**

1. **The gate FAILed at the canonical sleep=10 ($1,510 ≫ $200).** This empirically
   confirms §2: the break reproduces with `DAG_PARALLEL` unset (the gate never sets
   it), so the prior attempt's `dag_pipeline` pivot was operating on dead code. The
   DAG refutation is now empirical, not just static.

2. **The localized channel: live network leakage in `signals_advanced.py`.** The
   fingerprint diverges at **cycle 1** in `btc_dominance`, `long_short_ratio`, `vrp`
   — signals that make **direct `urllib` calls** (`fapi.binance.com` long/short ratio
   `:730`; CoinGecko `/api/v3/global` + CoinPaprika dominance `:871/:885`) gated only
   by a module-level `_FETCH_CACHE` 1h TTL keyed on `time.time()` (`:856`). These
   calls **do not respect `OMEGA_FROZEN_CACHE`** — that flag freezes `data_cache.py`
   (FRED/funding/macro) but not `signals_advanced.py`'s own fetches. Each replicate
   is a fresh process → fresh module cache → fetches **live** at its own startup
   wall-clock. `btc_dominance` = 0.3 (live value) vs 0.5 (neutral fallback when the
   API times out) is the discrete flip; the network is reachable *sometimes* (0.3≠0.5
   both ways proves it isn't uniformly offline), so the value drifts with real time.

   **One-sentence finding: `--frozen-cache` has a hole — it freezes `data_cache.py`
   but not `signals_advanced.py`'s direct `urllib` calls, so live data leaks into the
   "frozen" backtest.**

3. **Why this is the sleep-correlation (resolves the V213 mystery).** At sleep=0 all
   4 replicates finish within minutes → they fetch near-identical live data → spread
   small (V213's sleep=0 PASS). At sleep=10 each replicate takes ~40min, so r1→r4
   span ~2.5h of real wall-clock → live data (and API up/down state) drifts between
   them → spread large. Sleep was never a within-run determinism variable; it sets
   the **wall-clock separation between replicates**, which sets how much the
   non-frozen live inputs have moved. This also explains the deterministic
   sleep10→sleep0 recent PnL level shift and the bimodal 81↔83 entries (live-vs-
   fallback dominance flip crossing a discrete regime/conviction boundary).

4. **Reframing (strong inference — confirmation is V215's selector-OFF control).**
   This input non-hermeticity feeds the composite **regardless of the selector**, so
   it must make selector-OFF non-deterministic at sleep=10 too. That contradicts
   V212/V213's framing of the break as *selector-induced*. The coherent resolution:
   **the selector does not induce the non-determinism — it amplifies a pre-existing
   input leak.** OFF, the wobble is small (this is almost certainly V211's
   unexplained "residual 4th channel" — the 105-vs-106 trend outlier, ~$166); ON, the
   selector's discrete regime-label threshold sits on a near-boundary value and the
   live-data wobble flips the label, blowing the spread up to $1,500–$18,000. **Not
   yet established** — V214 only ran selector-ON; the selector-OFF-at-sleep=10 number
   is the missing control (V215).

5. **Not claimed:** that freezing these fetches collapses the spread. "Localized"
   ≠ "confirmed root cause" — a second channel could remain. Confirmation = V215's
   fix + re-gate to <$200. `dag_pipeline.py` was deliberately not modified (dead
   code, §2).

**No high-water** (diagnosis version; selector still not evaluable). All V211 highs
