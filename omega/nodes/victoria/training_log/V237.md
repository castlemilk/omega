## Hypothesis (one sentence)

Crisis losses are portfolio-level (correlated basket grind-down with no
cross-sectional spread to harvest — V231/V234 forensics), so a **whole-book
throttle triggered by a cross-ticker correlation spike** will cut the crisis
distribution's left tail where every per-name gate (signal/site/weight/sizing/
selection) could not.

## Design

- **Detector:** rolling mean pairwise correlation of daily returns across the
  active universe over a trailing 7-bar window, computed from the same frozen
  OHLCV the strategy already holds (Track B #2 confirmed computability in all
  windows). Bar-time only (V216 fence discipline); `math.fsum` for every
  cross-ticker reduction (V221 discipline).
- **Trigger:** corr > threshold C (grid: C ∈ {0.75, 0.85}) ⇒ throttle **NEW**
  position entries to 0 for the next K cycles (grid: K ∈ {5, 10}); existing
  positions unaffected (this is an exposure cap, not a liquidation rule).
- **Actuator:** the retained V234 site — `raw_weights` normalization in
  `strategy.py` (~3384) — scaling/zeroing the WHOLE book's new-entry weights, so
  the mechanism cannot be blind to which name loses (the exact blindness that
  killed V227–V234).
- **Flags:** `portfolio_corr_cap_enabled` (default OFF ⇒ byte-identical standing
  main), `portfolio_corr_cap_threshold`, `portfolio_corr_cap_cycles`.
  `assert_cell_identity` gains `--expect-corrcap` + a fired-cycles observability
  counter (fired==0 on a window is legitimate; the flag value is the identity).
