## Hypothesis (one sentence)

The cross-sectional demean (`_basket_mean`) is a degenerate one-factor model
with every beta pinned to 1; in high-correlation states (recent/chop, crisis)
the alts' true BTC betas run ~0.9–1.5, so the "idiosyncratic" signal the
system trades retains systematic factor contamination — replacing the demean
with a rolling-OLS BTC-factor residual (60d, frozen OHLCV only; BTC is in
every snapshot even though blacklisted from trading) removes a real defect
and should lift recent's mean/tail without regressing trend/crisis.

## Separator proof (FIRST, ~$0, no grid — V234 rule)

From the same 140 pooled recent main-arm trades + frozen snapshots used by
V236's analysis (entry bar = `cycle − hold_cycles + 28`, validated there):

- At each entry, estimate each traded name's rolling 60d OLS beta to BTC
  (fsum-fenced), and compute the **mis-demean contamination** the current
  construction injects: `|(β − 1) · r_BTC|` aggregated over the composite's
  lookback at entry (the residue the β=1 demean leaves in the traded signal).
- Gate (pre-registered): losers' median contamination > winners' at p < 0.05
  (Mann-Whitney, one-sided) AND the high-contamination tercile's pooled PnL
  is materially negative (< −$500) with a loss gradient in the right
  direction. Sensitivity at 40d/90d beta windows is diagnostic color only.
- Both prongs fail ⇒ **refuted at $0**, zero code; the queue advances to V238
  (feed build) with the tail cap and Section-4 conditional-expectancy surface
  as the remaining recent-targeted candidates.

## Hypothesis (one sentence)

Crisis losses are portfolio-level (correlated basket grind-down with no
cross-sectional spread to harvest — V231/V234 forensics), so a **whole-book
throttle triggered by a cross-ticker correlation spike** will cut the crisis
distribution's left tail where every per-name gate (signal/site/weight/sizing/
selection) could not.

## Design

- **Detector:** rolling mean pairwise correlation of daily returns across the
  active universe over a trailing 7-bar window, computed from the same frozen
  OHLCV the strategy already holds (Track B #2 confirmed computability in all
  windows). Bar-time only (V216 fence discipline); `math.fsum` for every
  cross-ticker reduction (V221 discipline).
- **Trigger:** corr > threshold C (grid: C ∈ {0.75, 0.85}) ⇒ throttle **NEW**
  position entries to 0 for the next K cycles (grid: K ∈ {5, 10}); existing
  positions unaffected (this is an exposure cap, not a liquidation rule).
- **Actuator:** the retained V234 site — `raw_weights` normalization in
  `strategy.py` (~3384) — scaling/zeroing the WHOLE book's new-entry weights, so
  the mechanism cannot be blind to which name loses (the exact blindness that
  killed V227–V234).
- **Flags:** `portfolio_corr_cap_enabled` (default OFF ⇒ byte-identical standing
  main), `portfolio_corr_cap_threshold`, `portfolio_corr_cap_cycles`.
  `assert_cell_identity` gains `--expect-corrcap` + a fired-cycles observability
  counter (fired==0 on a window is legitimate; the flag value is the identity).
