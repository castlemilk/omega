# V207a — Pin PYTHONHASHSEED + freeze funding cache (methodology-only)

**Date:** 2026-06-01
**Author:** claude
**Parent:** V206b (commit `27523d1`) — i.e. HEAD = V172-baseline strategy.py with V205 strip undone.
**Status:** complete — partial fix; V207b required

## Why V207a exists

V206b (commit `27523d1`) located **two compounding noise channels** that
explain why six consecutive versions (V199–V205) were reading dict-edit
noise as architectural signal:

1. **`PYTHONHASHSEED` is unset.** `scripts/run_training.py` seeds
   `random` and `numpy.random` at line 486–487 but does not pin
   CPython's per-process string-hash seed. Hash randomization permutes
   iteration order of `set` and string-keyed dicts in the signal
   composite, producing FP-summation drift of ~1e-4 in `composite_score`
   from cycle 1. Stable per-process bias, sub-dollar PnL in stable
   regimes, trade-set bifurcation in crisis.
2. **`data/macro_cache.db::funding_rate_cache` is live-fetched and
   rewritten at every run start.** `MacroDataCache.warm_up()` is called
   at line 535 even in backtest mode; `get_funding_rate` triggers
   `_refresh_funding` whenever the cached rate is > 8 h old, OKX/Coinbase
   INTX/CoinGecko HTTP responses get written back, and the next run
   reads run-1's freshly-fetched rates. Cross-day drift = $8k+ on trend
   per V206b's V204→V206b r1 delta with no code change.

V207a is **methodology-only** — no `strategy.py` change. Its job is to
**eliminate** the two noise channels and prove zero noise by byte-identical
artifacts across pre-registered no-op pairs. Until this passes, no new
strategy hypothesis runs.

## Hypothesis

**Pinning `PYTHONHASHSEED=42` + freezing `funding_rate_cache` reads in
backtest mode produces byte-identical `metrics.jsonl` (timestamp-stripped)
across no-op pairs on all 3 gates.** Equivalent to V206b's audit but with
the two fences in place. Trade CSVs (cycle/symbol/side/entry/exit/size/pnl
columns) should also be byte-identical within each gate's pair.

## Changes

- Files touched: `scripts/run_training.py` (env var pin + new flag),
  `omega/nodes/victoria/data_cache.py` (frozen-mode read path).
- Configs / preset name: default `v93_baseline`.
- Feature flags toggled: **none.**
- New CLI flag: `--frozen-cache` (or env-equivalent). When set, the macro
  cache:
  - skips `_refresh_funding` entirely — `get_funding_rate` returns the
    cached value via `_read_funding` directly (or `None` if not present);
  - skips `warm_up()` macro refreshes (existing rows are read; no FRED
    fetches).
  Default ON when `--backtest-snapshot` is set.
- `PYTHONHASHSEED` strategy: set `os.environ["PYTHONHASHSEED"]="42"` at
  the top of `scripts/run_training.py` BEFORE any other import. If the
  current process did not inherit that value, `os.execvpe` re-exec with
  the env var pinned. (Documented in code comment; this is the only way
  to make hash-seed pinning take effect on a process that's already
  imported anything.)
- Anything reverted vs parent: none.

## Procedure

For each gate ∈ {recent, trend, crisis}:

1. Record a pre-run fingerprint:
   `sha256sum data/macro_cache.db data/omega_victoria_state.db data/omega_victoria_memory.db`.
2. Run #1:
   ```
   PYTHONHASHSEED=42 python3 scripts/run_training.py \
     --version v207a_<gate>_r1 \
     --cycles 200 --sleep 10 --seed 42 \
     --backtest-snapshot data/snapshots/<snap>.json \
     --frozen-cache
   ```
3. Snapshot artifacts into `data/v207a_audit/<gate>_r1/`.
4. Run #2: identical command with `--version v207a_<gate>_r2`.
5. Snapshot artifacts into `data/v207a_audit/<gate>_r2/`.
6. Resilient launch: `setsid nohup … &; disown` per V204 pattern.

Snapshot mapping:
- recent → `data/snapshots/snap_20260414.json`
- trend → `data/snapshots/snap_trending_2023q4.json`
- crisis → `data/snapshots/snap_crisis_2022h1.json`

All six runs are sequential.

  IDENTICAL.
- `total_pnl_usd` and `total_closed` in `results.json` are IDENTICAL.

## Conclusion

### Byte-identical status per gate

**No gate byte-identical.** Per the pre-registered falsifier table this
maps to row 3: *"No gate byte-identical → fix is wrong/incomplete; V207b
= re-diff the artifacts with the fix applied to find what still drifts."*

### What V207a DID fix

1. **`PYTHONHASHSEED` is pinned.** Re-exec sets it to 42 before any
   import; `hash("victoria")` is now stable across processes (verified
   by isolated subprocess test before launch). Cycle-1 composite drift
   shrank on crisis (V206b 2e-4 → V207a 1e-4) which is consistent with
   *some* of the noise being hash-permutation-driven.
2. **Funding-cache writes eliminated.** `macro_cache.db` SHA-256 is
   byte-identical before and after all 6 runs (`FROZEN-CACHE VERIFIED`
   in `data/v207a_audit/run.log`). The cross-day $8k drift channel
   V206b identified on trend (V204→V206b: −$8,112 with no code change)
   is structurally closed.

### What V207a DID NOT fix — and why it got worse on recent + trend

A third noise channel dominates the metric. Cycle-1 `composite_score`
still drifts +3e-4 on recent and trend within the same V207a pair
(r1 vs r2) — and the downstream PnL spread is **vastly worse than V206b**:

- recent: V206b within-pair Δ=$0.08 → V207a Δ=$3,257 (40,000× worse)
- trend: V206b within-pair Δ=$0.49 → V207a Δ=$14,047 (28,000× worse)
- crisis: V206b Δ=$1,977.79 → V207a Δ=$113.42 (17× better — but trade
  count still bifurcates, 51 vs 60)

The trend trades.csv shows position sizes diverging by **exactly 2×**
(25000.0 vs 12500.0 on row 9), which is not floating-point drift — it
is a different number of open positions producing different position
sizing through the same allocator. This points to **macroscopic
ordering divergence in signal computation or position management**, not
just FP-summation noise.

Likely third channel (V207b suspects):

1. **`concurrent.futures.ThreadPoolExecutor` / asyncio task completion
   ordering** in signal fetch/compute. Multiple symbols computed in
   parallel, completion order determines summation order, and (more
   destructively) determines which positions get opened first when
   ring-buffer slots are limited.
2. **SQLite cursor ordering without `ORDER BY`** in semantic memory or
   any other read path used during composite computation.
3. **NumPy/sklearn random_state not threaded through** to every
   sub-component (one of `_apply_regime_adaptive_thresholds`,
   `_construct_portfolio`, `MetaHarness`, or the ensemble voter likely
   uses `np.random` directly without re-seeding per cycle).

Note: the V206b within-pair sub-dollar drift on recent/trend was
**precisely because** the live funding cache was hot and identical
across the two minutes between r1 and r2. With the cache frozen and
hash-seed pinned, V207a should be MORE deterministic — but it is not.
The third channel was being masked by the noise floor V206b reported.
This is consistent with V206b's reflection but contradicts the
*magnitude* implied there: the real noise floor without fences is not
sub-dollar; it is $3k–$14k on stable regimes once two other channels
are removed.

### Revised noise floor

**Cannot establish a zero-noise floor for V207a — the audit fails its
pass criterion on all three gates.** The post-V207a noise envelope is:

- recent: σ ≈ $3,257 within-pair (n=1 pair)
- trend: σ ≈ $14,047 within-pair (n=1 pair)
- crisis: σ ≈ $113 within-pair (n=1 pair), still with 51↔60 trade-count
  bifurcation

Crisis behaves qualitatively differently from recent/trend after the
V207a fences. The earlier "crisis is high-noise because of tight
conviction-threshold margins" model needs revisiting — crisis is now
the **lowest** within-pair $-spread of the three, but still bifurcates
trade count.
