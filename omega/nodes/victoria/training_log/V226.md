## Hypothesis

V225's lesson is mechanistic and unambiguous: an *always-on* downside tilt is a
**directional bias**, not a crisis signal — it fires every cycle (semivariance is
non-zero in any 30-bar window) and so it just shorts the bull on trend/recent. The
no-harm-by-construction assumption ("≈0 outside crisis") was **refuted** by the
`skew_on_cycles` ≈ 200 observability.

**Bet:** the same `crisis_skew` term, **conditioned to fire only when the runtime
regime label ∈ {crisis, high_vol}** (reusing the V223 gate-harness label as an
*enable* condition) **and at lower weight (W: 0.5 → 0.2)**, improves the **crisis**
gate by > $200 **without regressing trend or recent by > $200**. The gate collapses
`skew_on_cycles` from ~200 to the genuine crisis subset; on trend/recent (mostly
`normal` regime) the term should be suppressed → `skew_on_cycles < 40` → no-harm by
*construction enforced by the gate*, not by an (refuted) magnitude assumption.

**Effect-magnitude prediction:** crisis Δ between +$200 and +$2,000 (gated subset
of cycles × W=0.2); trend/recent Δ within ±$200 (term gated off in `normal`).

## The regime-label source (the critical design question)

The skew value is computed/applied inside `signal_generation.py` (the
`SignalGenerationNode` sub-node), which runs *before* this cycle's regime is
finalised in `victoria_node._do_compute_signals` (VRP→regime mapping at
`victoria_node.py:1062`, `_VRP_REGIME_MAP = {"FEAR":"high_vol","COMPLACENCY":
"crisis", …}`). So the authoritative label `signals["_regime"]` (what
`strategy._cycle_regime_label` reads) is **not available in-cycle** to the gate.

**Decision:** thread the **prior cycle's** consolidated `signals["_regime"]` into
the signal generator (`victoria_node` sets `self._signals._cycle_regime_label`
each cycle from `self._last_signals["_regime"]`). This is the same VRP-mapped
{crisis, high_vol, normal, bull, bear, sideways, default} label space the strategy
acts on, with a 1-cycle lag. The lag is immaterial for the experiment: regimes
persist for many consecutive cycles (a crisis snapshot is crisis for long stretches),
so only the single transition cycle is mislabeled. This is exactly the channel
fork #3 below tests — if the label distribution is wrong, the grid surfaces it.

## Determinism plan

The gate adds **branching only — no new float-accumulation site**. The skew value
fsum (in `crisis_skew.py`) and the 2-element post-composite add fsum (V225,
`signal_generation.py:1245`) are unchanged. `_regime_gated_skew` is a pure boolean
branch returning either the V225 value or `0.0`. W is a constant swap. The gate
counters are integer-only (observability), never a numeric path. Expectation:
**6/6 hermetic at $0.00**. Any FAIL ⇒ auto trade-diff (obs #14) names the field.

## Pre-committed risks + mitigations

- **Regime label never reaches {crisis,high_vol}** (gate skips always → fork 2/3).
  Mitigated by sourcing the *authoritative VRP-mapped* `_regime` (not the orchestrator
  context regime, which is fed a different key and may stay `normal`). The smoke test
  (Step 4) verifies `skew_on_cycles` varies per snapshot *before* the grid.
- **1-cycle lag mislabels the transition cycle.** Immaterial for persistent regimes;
  fork 3 surfaces it if it isn't.
- **Cell-identity FAILs on gated-to-zero skew-ON cells.** Mitigated by the gate-aware
  `--expect-gate on` mode (relaxes the >0 inertness check to "gate was evaluated").
