## §1 — Hypothesis

V273's H3 named `ic_seed_weighting` and `per_regime_ic_weighting` (`features.py:680`,
`:688`) as **defaults-ON** while every grid arm that produced the standing baseline
types `"ic_seed_weighting": false` by hand. V274 then **cleared** the baseline: all
32 cells recorded the flag explicitly false, and re-running at 0.000000 drift proved
the measuring stick is causal.

So the baseline is clean **by convention, not by construction**. The bet:

> Flipping the `features.py` code default to `False` makes the convention structural.
> Because every arm already sets the flag explicitly, the flip is a **no-op for every
> existing arm** — and a regression test makes the defect class unable to return
> silently.

**Falsifier (G2):** if any representative cell moves by a cent, the flip has surfaced
a hidden reliance on the default somewhere the audit missed. That is the finding —
**STOP and report as R5**, do not chase the fix in this version.

## §2 — Phase 0 (G3): the default-reliance audit, run BEFORE the flip

The premise of the flip is *"no arm relies on the True default."* Phase 0 tests that
premise mechanically rather than assuming it. Instrument: an ad-hoc read-only scanner
over every feature-JSON arm assigned in `scripts/*.sh` (44 arms across 26 scripts),
classifying each flag as *explicit* or *INHERIT(default)*.

### Result — the premise SPLITS

| Flag | Arms inheriting the `True` default | Premise |
|---|---:|---|
| `ic_seed_weighting` | **0 / 44** | **HOLDS** |
| `per_regime_ic_weighting` | **44 / 44** — of which **7 are load-bearing** | **FALSIFIED** |

`per_regime_ic_weighting` is absent from *every* arm in the repo. In the 37 arms that
run `ic_seed_weighting: false` it is **doubly inert** (V274 §: `_regime_ics` has no
populate path outside the `ic_seed_weighting`-gated block at
`scripts/run_training.py:1105-1155`, so the per-regime lookup finds an empty dict and
falls back to pooled — which is also empty). In the **7 arms that run
`ic_seed_weighting: true`, `_regime_ics` IS populated and the flag IS live:**

| # | Arm | Version |
|---|---|---|
| 1 | `scripts/v224_run_grid.sh:37` `R3F` | V224 |
| 2 | `scripts/v228_run_grid.sh:15` `ON` | V228 |
| 3 | `scripts/v229_run_grid.sh:18` `ON` | V229 |
| 4 | `scripts/v229_xsweep.sh:11` (function-local `feats`) | V229 |
| 5 | `scripts/walk_forward_grid.sh:51` `TRENDIC` | V235-era |
| 6 | `scripts/v274_ic_on_grid.sh:38` `ARM_ON` | **V274** |
| 7 | `scripts/v274_smoke.sh:32` `ARM_ON` | **V274** |

Arms 6 and 7 are the ones that matter: `v274_ic_on_grid.sh:36` says so **in a
comment** — *"per_regime_ic_weighting is left at its features.py default"*. V274's
headline result (IC-ON moves all 32 cells / 8 sign flips, nets inside every MDE) was

redefine V274's own IC-ON arm: re-running `scripts/v274_ic_on_grid.sh` at post-flip
HEAD would measure a *different* arm than V274 measured, and report the same label.

That is the same reproducibility defect V275 exists to close, pointed the other way.

### Consequent scope decision (pre-registered, before the flip)

- **`ic_seed_weighting`: FLIP to `False`.** Premise verified over all 44 arms.
- **`per_regime_ic_weighting`: DO NOT FLIP.** Premise falsified. Reported, not
  silently changed, per the operator's standing instruction.

The correct sequence for the second flag is a follow-up version: **first** pin
`"per_regime_ic_weighting": true` explicitly into the 7 IC-ON arms above (a no-op
edit that preserves what they measured), **then** flip the default. Doing it in the
other order rewrites history. Queued as V276-hygiene; not run here.

## §4 — The regression test (exact content, pre-registered)

`tests/test_features_defaults.py` pins **both** flags to their audited values, so
neither can drift silently in either direction:

- `test_ic_seed_weighting_defaults_off` — asserts `VictoriaFeatures().ic_seed_weighting is False`.
  **This is the test that would have caught the V273/H3 defect.** It FAILS on pre-flip code.
- `test_per_regime_ic_weighting_default_is_pinned_true` — asserts the default is
  **still `True`**, and carries the §2 audit in its docstring: this flag may only be
  flipped *after* the 7 IC-ON arms are pinned explicitly. A future flip must
  deliberately edit this assertion, which forces the author to read the reason.
- `test_ic_flags_have_no_strategy_layer_consumer` — asserts `ic_seed_weighting`
  appears in exactly one executable consumer (`scripts/run_training.py`), guarding
  the §2 row-2 claim that the flip cannot change strategy behaviour.

## §7 — Conclusion

**SHIPPED, with the scope halved by its own Phase 0 — and the halving is the finding.**

`ic_seed_weighting` now defaults `False`. IC weighting is something an arm opts into,
not something an arm inherits by forgetting. The convention V274 verified is now
enforced by `features.py` and pinned by `tests/test_features_defaults.py`, and the
standing baseline is unchanged: crisis +$599 / trend +$2,997 / recent +$30, with all
three representative cells reproducing to the cent at $0.00 determinism spread.

**The finding is that the brief's premise was only half true.** *"No arm relies on
the True default"* holds for `ic_seed_weighting` (0 of 44 arms) and is **false** for
`per_regime_ic_weighting` (44 of 44 inherit it; 7 live IC-ON arms depend on it —
including `scripts/v274_ic_on_grid.sh:38` and `v274_smoke.sh:32`, V274's own ARM_ON,
whose comment states the reliance outright). Flipping that second default would have
silently redefined the arm behind V274's headline result — the same reproducibility
defect V275 exists to close, pointed backwards. It was left at `True` and the
sequencing moved to §8.

The general lesson, now in `CONTRIBUTING.md`: **a flag's default is what an arm gets
when it forgets.** Two flags declared in the same commit, documented in the same
paragraph, with defaults that looked equally wrong — and one was safe to flip while
the other was not. The difference was invisible from the flag definitions and only
visible from the *arms*. Auditing who inherits a default is not a formality before
changing it; it is the change's only real risk, and it belongs in the
pre-registration.
