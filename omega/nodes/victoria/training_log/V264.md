## 1. Why this version exists

V263's STOP was explicitly scoped to the **zero-shot** case, and its own §"What
would reopen this lane" names fine-tuning as reopener (1):

> *"Zero-shot failure on crypto 1h is genuinely uninformative about the fine-tuned
> case; the model was pretrained on a mix our universe is a small and unusual
> corner of. This is the only serious rehabilitation path."*

That is a real gap, not a consolation prize. Kronos's pretraining mix is
equity/A-share-heavy; V263 even measured a **systematic unconditional short bias**
(forecast up-rate 0.46 vs realized 0.51) consistent with an inherited prior that
does not match our universe's drift. A model whose prior is mismatched can be
directionless without being incapable.

V264 closes that gap the only way it can be closed: **fine-tune on our corpus and
re-run the identical gate.** Either the lane opens or it closes cleanly.

## 2. Alpha thesis (pre-declared)

> Fine-tuning Kronos on the V262 1h crypto corpus produces a forecaster with
> directional edge on OUR universe and frequency that the zero-shot model lacked.
> The foundation model supplies general K-line structure; fine-tuning specialises
> it to crypto 1h regime structure (24/7 trading, no session boundaries, fat tails,
> volatility clustering the zero-shot model demonstrably under-modelled at a
> forecast/realized dispersion ratio of 0.31–0.39).

### 2a. The load-bearing assumption

Same as V263: **forecast accuracy is not alpha**, and a model failing on *both*
error and direction has nothing to trade. F4-ft remains the cheap separator that
gates all downstream work (standing rule from V234).

The new failure mode V264 must avoid is **train/test contamination**. V263 scored
windows spanning 2020→2026. V264 fine-tunes on 2020–2023. Comparing a fine-tuned
model on 2025–2026 against V263's full-span number would flatter the fine-tuned
arm for free. See §4a.

## 3. Method (pre-declared)

| Item | Choice | Rationale |
|---|---|---|
| Base model | **Kronos-small** (24.74M) + `Kronos-Tokenizer-base` (3.96M) | Same pair V263 refuted zero-shot. Holding the architecture fixed isolates fine-tuning as the only changed variable. |
| Corpus | V262 frozen 1h, `data/frozen_series/binance_intraday/` | 665,824 bars, 14 symbol dirs, byte-identity verified. No new freeze. |
| Split | **train ts < 2024-01-01 · val 2024 · test ts ≥ 2025-01-01** | Strictly temporal, disjoint by date. 373,871 / 114,113 / 177,840 bars. |
| Window | lookback 400 + predict 24 (+1) = 425 bars | Matches V263's inference regime exactly, and fits the 512 hard context. |
| Device | **MPS** (Apple GPU) | No CUDA on this host. |
| Epochs | **3 tokenizer, 3 predictor** | Deliberately small. Scale only if the loss curve says it helps — never until the gate passes (anti-Goodhart). |
| LR | 2e-4 tokenizer / 4e-5 predictor | Upstream `finetune/config.py:58-59` defaults, unchanged. |
| Losses | upstream, verbatim | tokenizer `(recon_pre + recon_all + bsq)/2`; predictor `head.compute_loss` on next-token s1/s2. |

### 3a. Why V264 does not use `third_party/kronos/finetune_csv/` as-shipped

Two blocking defects for this host and this experiment, both found at Phase 0:

1. **No MPS branch.** `finetune_tokenizer.py:291` and `finetune_base_model.py:375`
   both read `device = cuda if torch.cuda.is_available() else cpu`. On this Mac
   that silently trains on CPU.
2. **Single-CSV, ratio split.** `CustomKlineDataset` reads one CSV and splits it by
   row *ratio*. Concatenating 13 symbols into one CSV lets a sliding window
   straddle a symbol boundary (BTC history → SOL forecast), and a ratio split
   cannot express the date split above.

V264 therefore ports the pipeline into `scripts/v264_kronos_finetune.py` — same
feature layout, same per-window z-score + clip(5.0) normalisation, same losses,
same AdamW/OneCycleLR schedule, same grad-clip norms (2.0 / 3.0) — with a
multi-symbol dataset whose windows never cross a symbol boundary. Vendored code is
left unmodified.

**Window subsampling.** Consecutive 425-bar windows overlap >99%, so training
strides over start indices (tokenizer 4, predictor 6 → 92,096 / ~61,000 windows
per epoch). This is a redundancy decision fixed **before any result was seen**, not
a tuning knob.

## 4. Falsifiers — LOCKED, carried over from V263 with no adjustment

| ID | Falsifier | Bar | Stage |
|---|---|---|---|
| **F4-ft** | Fine-tuned forecast direction correlates with realized direction better than chance | **pooled Spearman ρ > +0.05** | V264 Phase 4 |
| **Stretch F1-ft** | RMSE ratio vs naive < 1.0 | on ≥ 4 of 8 pre-declared cells | V264 Phase 4 |
| **Quality** | Fine-tune is mechanically sound | train loss decreases AND val loss does not diverge | V264 Phases 2–3 |

The eight cells are **V263's, unchanged**: BTCUSDT h{1,4,12,24}, SOLUSDT h{1,24},
XRPUSDT h{1,24}. `sample_count=8` (V263's fairness fix), 405 windows per cell.

### 4a. Anti-Goodhart controls

- **The +0.05 bar is locked at V263's value.** No post-hoc adjustment, in either
  direction, for any reason.
- **The zero-shot control is re-run on the holdout.** V263's ρ = −0.027 is measured
  over 2020→2026, which is now 63% training data. It is reported for continuity but
  it is **not** the control. The honest delta is
  `finetuned(2025–2026) − zeroshot(2025–2026)` on the identical window set.
- **Windows sit entirely inside the holdout** — the 400-bar lookback start, not
  just the forecast anchor, is ≥ 2025-01-01. No forecast can condition on a bar the
  model trained on.
- **Epoch count is not tuned against F4-ft.** Train what is mechanically sensible,
  then check the gate once. Training until the gate passes is the exact Goodhart
  move this campaign has spent 30 versions learning not to make.
- Bonferroni across all 8 cells; drift confound (realized vs forecast up-rate),
  balanced accuracy and MCC reported alongside raw accuracy.
- Seeded sampling; per-batch seeds are deterministic in the window index.
