## Hypothesis

**Freeze every live `urllib` fetch in the Victoria signal layer during a frozen
backtest, and the determinism break collapses below the $200 fence.** V214 proved
the channel is input non-hermeticity: `OMEGA_FROZEN_CACHE` freezes `data_cache.py`
(FRED/funding/macro) but **not** the direct `urllib.request.urlopen` calls in
`signals_advanced.py` and ~25 sibling signal modules. Each replicate process is
fresh → fresh module cache → fetches **live** at its own startup wall-clock; at
sleep=10 the r1→r4 span (~2.5h) lets live data (and API up/down state) drift,
blowing the spread to $1,510. Block all outbound HTTP in frozen mode and every
signal degrades to its **deterministic fallback** (constant), so replicates become
byte-identical regardless of wall-clock separation.

This is the same class of fix as the WS-stub at `run_training.py:506` (backtest
mode disables live WS feeds); V215 extends the hermeticity guarantee from WS feeds
to HTTP fetches.

### Implementation approach (the value-choice, pre-registered)

Two mechanisms, mirroring the user-specified **A + C** bias:

**C — centralized HTTP guard (the determinism guarantee).** In `run_training.py`,
when `OMEGA_FROZEN_CACHE=1`, monkeypatch **`urllib.request.OpenerDirector.open`**
(NOT `urllib.request.urlopen`). Rationale: patching `urlopen` only catches callers
that invoke it as a module attribute; `signals/whale_flow.py` uses
`from urllib.request import urlopen` (bound at import → a `urlopen` patch silently
misses it). `OpenerDirector.open` is the **import-style-agnostic chokepoint** —
every `urlopen()`, however imported, routes through the global opener's `.open()`
at call time, so a class-method patch catches all of them. A repo sweep confirms
urllib is the **only** HTTP mechanism in the Victoria layer (no `requests`/`httpx`/
`aiohttp`), so this one patch is airtight. (Socket-level blocking was rejected — it
would kill the Postgres `DATABASE_URL` connection; `OpenerDirector.open` is the
correct altitude.) The guard:
- raises `urllib.error.URLError` on every call → caught by every signal module's
  broad `except Exception` → **deterministic fallback**, run completes;
- appends the URL to `data/{version}_http_during_backtest.jsonl` (loud, append-only);
- increments a counter surfaced in results `observability.http_blocked_count`.

**A — snapshot freeze (realistic values for the 2 localized signals).** Rather than
let `btc_dominance`/`long_short_ratio` degrade to the neutral 0.0 no-data fallback,
`signals_advanced.py` returns **snapshot-derived values** from a committed
`data/frozen_advanced_signals.json` when `OMEGA_FROZEN_CACHE=1`. The value choice
(pre-registered): **(b) snapshot-derived** — a one-time live capture committed to
the repo, NOT a neutral constant and NOT last-cached-pinned. This keeps the two
highest-signal feeders at a realistic recent level (e.g. dominance ≈ 0.58) so the
hermetic baseline stays close to live behaviour, while still being fully
deterministic. `vrp`/Deribit and all ~25 other modules are handled by C alone
(blocked → deterministic fallback) — chasing each one individually is whack-a-mole;
C neutralizes the whole class at one chokepoint.

**Why both:** C alone already guarantees determinism (block-all → constant
fallbacks). A only buys *realistic* values for the two signals V214 localized, so
the hermetic baseline isn't gratuitously far from live. With the guard raising on
**100% of network attempts**, any residual spread is **definitionally non-network**
— a strictly stronger discrimination than an empty-jsonl check.

## Conclusion

**Mixed but decisive: the bet (network freeze) is CONFIRMED and the dominant
channel is CLOSED; the gate still FAILs on a SECOND, non-network, sizing-side
channel that V215's own instrumentation localized in one shot.**

1. **Network channel — CONFIRMED + FIXED.** `on_r1 == on_r2` byte-identical
   (−$7,880.00, 70 trades) and **all 200 signal fingerprints identical between
   on_r1 and on_r4**, and between off_r1 and off_r2. The V215 freeze made the
   signal layer hermetic at sleep=10 — the confirmation V214 deferred. The
   `--frozen-cache` hole is closed. The guard blocked **2,637 live HTTP calls per
   run** (identical count every replicate → deterministic), confirming the leak
   was **far broader than V214's 3 localized signals**: FearGreed, Binance
   ticker/funding, GitHub dev-activity, news RSS (cointelegraph/cryptopanic),
   onchain MVRV (raw.githubusercontent), CoinGecko/CoinPaprika. The whole signal
   layer was non-hermetic; the centralized `OpenerDirector.open` guard (option C)
   neutralized all of it — per-call option-A fencing would have missed ~25 of them.

2. **Gate FAILs on a sizing-side wall-clock channel (Falsifier 1, but fully
   diagnosed — not mysterious).** `core/risk_manager.py:316` `time_risk_multiplier`
   defaults its `now` arg to `datetime.now(UTC)` and `_TIME_RISK_WINDOWS` (line 69)
   applies a **0.50 size multiplier during 14:30–15:30 UTC** (US market open). It
   reads **real wall-clock**, not the bar timestamp, so a backtest replicate that
   straddles the window halves its position sizes mid-run. The evidence is airtight:
   - **Non-network by construction** — the guard raised on 100% of HTTP (2,637/run),
     so any residual spread is *definitionally* non-network.
   - **Downstream of signals** — fingerprints identical (Falsifier 2 signature): the
     divergence is in sizing/selection, not a signal value.
   - **Timing-locked** — on_r4 ran *entirely* inside 14:30–15:30 → 46 trades vs 70;
     on_r3 clipped only its last cycle → +$134; on_r1/on_r2 clear → identical. OFF:
     off_r1 (partial window) vs off_r2 (clear) → $2,717 spread.
   This is **exactly the V214 §1 parking-lot site** ("`risk_manager.py:332` time-risk
   multiplier 14:30–15:30 … a reproducibility hazard if a run spans their windows"),
   now realized. V215's guard + per-replicate wall-clock stagger *is* the diagnostic
   that surfaced it.

   **Mechanism CONFIRMED by the trade CSVs (not just inferred from timing).** Aligning
   `on_r1` (no window) vs `on_r4` (full window) by `(cycle, symbol, side)`: the **size
   ratio r4/r1 on the 43 common trades has median exactly 0.500** (35/43 at 0.5×) —
   the `time_risk_multiplier=0.50` applied, directly observable in the `size` column.
   The trade-count drop (70→46) is the **second-order** effect: the 27 trades present
   in r1 but dropped in r4 are the **smallest** (median size 7,082, conviction
   0.05–0.10) vs the 43 kept (median 15,000) — halving the size pushes the marginal
   low-conviction trades below the min-size/notional floor. So the chain is
   size-cut → small-trade drop-out, both legs evidenced, not assumed.

3. **Selector reframe (V214 #4) — CONFIRMED.** OFF also FAILs at sleep=10
   post-freeze ($2,717), and its failure is the *same* sizing-time channel (off_r1
   straddles the window, off_r2 doesn't). So the residual non-determinism is
   **selector-INDEPENDENT** — the selector does *not* induce it. The network leak
   the selector was thought to amplify is gone; what remains is selector-independent
   sizing-time. V214 #4's "amplifies, not induces" framing is vindicated, with the
   correction that the surviving channel is sizing-side, not the network leak itself.

4. **Preliminary clean selector cost on trend ≈ −$22k (STRONG but pre-final).** The
   two *no-window* replicates isolate the selector flag with everything else held
   (time_risk_mult=1.0 for both, signal layer hermetic, same seed/sleep):
   **ON = −$7,880 (PF 0.747, losing)** vs **OFF off_r2 = +$14,110 (PF 1.43,
   winning)** → the selector costs trend **≈ −$21,990** and flips it from profitable
   to losing. This sharpens V212's "−$583 recent / trend unmeasurable": on the
   hermetic baseline the selector is **catastrophic for trend**. Caveat: this is two
   replicates, not a full N-seed audit — V216 confirms it once the sizing-time
   channel is fenced. But the direction and magnitude are not noise (signal layer is
   byte-identical; the gap is real selection/sizing behaviour).

5. **No high-water; no full audit.** All V211 highs stand (selector still not
   cleanly evaluable until the sizing-time channel is fenced). The eval is *one
   channel away* from hermetic. **Baseline shift is real and broad** (per the
   pre-reg caveat, broader than estimated): hermetic trend is −$7,880 (ON) /
   +$14,110 (OFF) vs V214's wall-clock-leaky ~+$15k. Pre-freeze numbers stay
   historical; the V215 hermetic numbers are the new working baseline anchor.
