## §1 — Hypothesis

`scripts/check_determinism.sh` snapshots **four** files as a run's state. The V219
manifest asserts **one** of them. The mechanism that caught the `cfb4a43d`
`macro_cache.db` drift — and correctly refused to produce a baseline on it — is blind
to the other three, and `cfb4a43d` mutated `omega_victoria_memory.db` too with nothing
anywhere reporting it.

Worse, the codebase *declares* those files stable. `scripts/run_training.py:179-181`:

> *"STABLE/COMMITTED INPUTS stay anchored to DATA_DIR so frozen-cache determinism is
> untouched: training_version.txt, .cache_manifest.json, macro_cache.db,
> **signal_ic_history.json**, empirical_ic_history.json, **the state/memory DBs**, and
> data/snapshots/."*

The bet:

> Extending the manifest to the state files closes the blind spot the same way V219
> closed it for the macro cache — an md5 asserted at startup, a run that aborts rather
> than produce a baseline on drifted substrate.

## §1b — Phase 0 already falsified the naive form of this bet

`V277_PHASE0_ENV_BISECT.md` §4 item 1 recommended pinning **all three**. A probe run
(one 3-cell pass, md5 before/after) shows that recommendation was **wrong**:

| File | md5 stable across a run? |
|---|---|
| `data/macro_cache.db` | yes (already pinned) |
| `data/omega_victoria_state.db` | **yes** |
| `data/omega_victoria_memory.db` | **NO** — `5e34299…` → `b272ad5…` |
| `data/signal_ic_history.json` | **NO** — `a0e52d5…` → `3b9633c…` |

Two of the three are rewritten by every run (`signal_decay.py:82` persists IC history;
the semantic-memory store writes the memory DB via `run_training.py:314`). **Pinning
them as asserted entries would abort every run after the first** — it would convert a
silent blind spot into a hard, self-inflicted outage, and the V219 tripwire would be
firing on its own exhaust.

So the declared contract at `:179-181` is **false for two of the files it names**, and
that three-way inconsistency — declared stable / not pinned / actually mutated — is the
real finding. V277 changes the bet accordingly:

> **Assert what is provably stable; RECORD what is provably volatile; and never assert
> a file the run itself writes.** A recorded-but-unasserted hash still turns an
> invisible drift into a visible one, which is the whole value V219 delivered.

**Falsifier (G3):** if the preflight fails *after* a normal run completes, V277 has
pinned something the run mutates and is a footgun — **STOP and revert**, do not
special-case it.

## §2 — Change surface (4 files)

1. `scripts/build_cache_manifest.py` — add `data/omega_victoria_state.db` to
   `_FROZEN_FILES`; add a new `_VOLATILE_FILES` list (`omega_victoria_memory.db`,
   `signal_ic_history.json`) emitted into a separate `volatile_files` block with a
   `_volatile_note` explaining why they are recorded and not asserted.
2. `data/.cache_manifest.json` — regenerated by (1). **This is the one hand-checked
   output:** the three existing hashes MUST be byte-identical to their current values,
   since V277 changes no substrate. Any movement there is a red flag, not a rebuild.
3. `scripts/run_training.py` — after the existing `files` loop, report `volatile_files`:
   log each at INFO when it matches, and at **WARNING** when it has drifted, naming the
   file and both hashes. **Never aborts.** The existing abort on `files` is untouched.
4. `tests/test_cache_manifest.py` (**new**) — §4.

**Not touched:** any `omega/nodes/**` file, any strategy line, any grid script,
`data/standing_baseline.json`, the frozen substrate itself.

## §3 — Why `volatile_files` is not just a comment

A comment saying "these drift" is what `:179-181` already is, and it was wrong in both
directions for three years of commits. A recorded hash is falsifiable: it names the
value at the last deliberate rebuild, so a reader (or a future bisect like Phase 0's
row 4) can ask *"has this moved since?"* mechanically instead of by hand. That question
is exactly what Phase 0 had to answer with a manual `git checkout` + re-run.

### G3 — PASS (the falsifier, and it proved itself mid-run)

After a full run the asserted set is still clean (all 4 match) and fresh cells start


and every cell after it. The split is what makes the widening safe.

### An honest nuance on `omega_victoria_memory.db`

The Phase 0 probe measured it drifting (`5e34299…` → `b272ad5…`); the G2/G3 runs left
it **unchanged**. Its mutation is therefore **intermittent** — conditional on something
neither probe isolated — while `signal_ic_history.json` drifts on every run. This does
not change its classification: a file that *can* drift must not be asserted, or the
tripwire becomes a latent, intermittently-firing outage, which is worse than a loud one.
Recorded is the correct treatment for both. The condition under which the memory DB
writes is **not** characterised here and is left open.

## §6 — Conclusion

**Shipped. The manifest now covers three of the four files the determinism harness
snapshots, and the fourth is recorded rather than silently ignored.**

The version is worth more for what Phase 0 stopped than for what it added. The obvious
form of this change — "pin the three unpinned files", written into
`V277_PHASE0_ENV_BISECT.md` §4 by its own author — would have shipped a repo in which
the second training run of every session aborts on the first run's exhaust. It took one
cheap probe (md5 before/after, one 3-cell pass) to falsify, and that probe existed only
because the loop mandates a separator before committing to a mechanism.

**The finding underneath is a three-way inconsistency.** `run_training.py:179-181`
declares `signal_ic_history.json` and "the state/memory DBs" to be *"STABLE/COMMITTED
INPUTS"*. The manifest pinned none of them. And two of the three are rewritten by every
run. Declared stable / not pinned / actually mutated — three sources of truth, no two
agreeing, and no mechanism anywhere that would have reported the disagreement. That is
the same shape as V275's finding about `per_regime_ic_weighting` (a default whose
behaviour was only visible from the *arms*, never from the declaration) and the same
shape as the `cfb4a43d` drift itself.

**What this version does NOT fix:** runs still write to files the code calls stable
inputs. V277 makes that visible; it does not stop it. That is a real defect with a real
consequence — it is plausibly how a drifted `macro_cache.db` came to be committed in the
first place (run, then `git add -A`) — and it is deliberately left for V278 rather than
bundled here.

**Standing baseline: UNCHANGED and NOT edited.** No performance claim is made; every
gate in this version is a reproduction or a control.
