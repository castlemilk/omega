## §1 — Hypothesis

Phase 0 established that all four members of the `cross_asset` signal family are exactly
`0.0` in every frozen backtest, that none is ever injected into a ticker's signal dict
(`signal_generation.py:1223-1230` inserts only non-zero values), and therefore that the
family contributes nothing to the standing baseline while `AdaptiveCombiner` computes a
family weight over an empty set.

It took a four-step probe to learn that. The V213 startup banner — built *precisely*
because the V148–V202 arc burned four-plus versions tuning subsystems that never ran —
did not surface it, because it reports **flag wiring** (`UNDECLARED — getattr→False`,
`ON · module importable → ACTIVE`) and says nothing about a correctly-declared,
correctly-imported signal whose **value** is identically zero.

> **The bet:** the same class of finding — *"this thing you think is contributing is
> contributing nothing"* — is one aggregation away from being a single greppable line,
> over data the run already computes.

**Falsifier (G3):** if the report does not independently mark `cross_asset` **INERT** in
a real frozen run, it does not reproduce the Phase 0 finding and is not worth shipping.

## §2 — What this version is NOT

- **NOT a fix for the inertness.** `vix_signal`/`spy_signal` are zero *by correct design*
  (the V226/V227 determinism fences); unfencing them would reintroduce a live-HTTP leak
  into frozen runs. Phase 0 §5 says this explicitly. The goal is that inertness is
  **visible**, not that it is removed.
- **NOT a change to any signal, weight, threshold or gate.** Logging only.
- **NOT a second family map.** The report reads
  `AdaptiveCombiner.SIGNAL_FAMILIES` (`adaptive_combiner.py:48`), the existing source of
  truth. Duplicating it would create exactly the declared-vs-actual drift V276/V277 spent
  two versions closing.

## §3 — Change surface (2 files)

## §5 — Results

Run 2026-08-27, `sleep=0`, `cycles=60`, `N=2` — the V240 condition. All gates PASS.

### Deviation from §3, recorded not hidden

§3 declared a 2-file surface. It shipped as **3**: `scripts/run_training.py`
`_setup_logging` gained a 5-line block. Reason, found by G3 failing on its first
attempt: `basicConfig(level=WARNING)` puts the **root** logger at WARNING, and the INFO
handlers are attached only to `training.<version>`. Module-level INFO was therefore
suppressed — which is *why the V213 wiring banner is visible* (it logs via that logger)
*while `signal_generation`'s own startup lines never have been.* The fix routes that one
module's INFO to the same handlers; its INFO is ~22 one-time init lines, not per-cycle
traffic. Nothing else is re-levelled.

That first G3 failure is worth keeping: the report was correct and invisible, which is
the same failure mode — a thing that silently does nothing — that the report exists to
catch.

names it. Also pinned: fires once per process (a startup banner, not 60 log lines), and

### What that does and does NOT mean (both stated, because the first draft of this got it wrong)

**It does NOT mean the strategy runs on one signal.** `SIGNAL_FAMILIES` is
`AdaptiveCombiner`'s taxonomy of *per-ticker `*_signal` keys*. The **victoria_node signal
groups** are a *different* taxonomy, and the same run's fingerprint shows many of them
non-zero (`cross_asset.value=0.121` from the `CrossAssetSignal` **node**,
`microstructure.value=0.047`, `long_short_ratio.value=-0.191`, `btc_dominance.value=0.5`,
`_signal_count=20`, `_signal_coverage=0.87`). Phase 0 §3 warned that `cross_asset` names
two unrelated things; the same trap applies to `microstructure`, which appears in **both**
taxonomies with different meanings and opposite liveness. Conflating them is how V278 §7
reached an over-claim, and it is worth stating twice.

**It also does NOT mean adaptive weighting is broken.** The run emits no
`AdaptiveCombiner initialized` line — the combiner is flag-gated and **not active** in
the standing configuration. So this is evidence about **which `*_signal` keys exist in
ticker dicts**, not evidence that a live component is weighting an empty set. That
stronger claim would need a run with the combiner on, and is not made here.

**What it does mean:** of the 20 per-ticker signal keys the family map names, 19 never
appear in a frozen backtest. Any version that tuned one of those 19 under
`OMEGA_FROZEN_CACHE=1` was tuning a key that is never inserted — the V148–V202
runtime-inert failure mode, at a scale one line of output now makes obvious.

## §6 — Conclusion

**Shipped, and it earned its keep on the first run.** The report reproduced Phase 0's
`cross_asset` finding unprompted, then surfaced six more inert families that no probe had
been aimed at — at $0.00 PnL delta and $0.00 determinism spread.

The V213 banner answers *"is this subsystem wired?"*. This answers *"does anything
actually come out of it?"* — and the V148–V202 arc, the V219→V221 channel peels, and this
session's own four-step `cross_asset` probe are all cases where the second question was
the one that mattered and nobody could ask it cheaply.

**The most useful thing here is a scoping correction, not a headline.** Two signal
taxonomies share names (`cross_asset`, `microstructure`) with opposite liveness. V278 §7
tripped on it, V279 Phase 0 §3 documented it, and the first draft of this very section
tripped on it again in the other direction. The report is scoped to one taxonomy and
says so; nobody should read `momentum 1/3 live` as "the strategy has one signal."

**Standing baseline: UNCHANGED and NOT edited.** No performance claim; both empirical
gates are reproductions.
