## Hypothesis (pre-registered)

A supervised daily UTC scheduler + atomic crash-safe checkpoint can turn the
V250/V251 live-paper harness into a "leave it running and go away" daemon —
running headless for 90+ days without human intervention — while **preserving
the V251 bit-exact reconciliation property**. Concretely we bet that:

1. The scheduler can fire once per UTC day at a fixed time and run **headless
   indefinitely** with drift bounded well under a minute (no drift accumulation).
2. A killed-mid-cycle daemon can **restart from checkpoint** with the correct
   open-positions / equity / signal-state, reproducing exactly the state it had
   before the crash.
3. The daemon emits **daily PnL log entries** in strictly monotonic `cycle_ts`
   order.
4. Replaying V251's three sentinel windows through the daemon's retrospective
   path reproduces the **same** per-window PnL V251 recorded
   (crisis $1,149.76 / trend $4,679.67 / recent $771.98) — i.e. wrapping the
   *unchanged* eval in the runner does not perturb a single trade.

This is **pure runner-layer infra**: `strategy.py`, `signal_generation.py`,
`features.py`, `reasoning_layer.py`, `paper_trading.py` are all untouched. No
live-broker, no orders, no funds — simulated PnL against real / frozen market
data only.

## Falsifier (hard — ANY of these = REFUTED, do NOT merge)

- Scheduler drifts more than **60 s** vs its UTC target over 3 simulated days.
- Checkpoint corruption after a simulated crash (positions/equity restored wrong).
- Reload after crash does **not** byte-match a clean-start run on the same input
  dates.
- PnL log ordering is not strictly monotonic on `cycle_ts`.
- Backtest byte-identity broken (V240 confirm sentinels diverge post-merge).
- Live-poller frozen-path guard trips (`FrozenPathViolation`).

All three deterministic smoke tests PASS (`tests/test_live_paper_scheduler.py`
for A/B, `scripts/v252_reconcile_smoke.py` for C). Every falsifier cleared.

**Test A — 3-day forward simulation (scheduler timing + daily checkpoint): PASS**

| Metric | Result | Gate |
|---|---|---|
| Ticks fired at exact UTC targets | 2026-08-0{1,2,3}T04:05:00Z | ✅ |
| Max abs drift over 3 days | **2.0 s** (constant, non-accumulating) | < 60 s ✅ |
| Drift with injected NTP jumps (+8 s / −5 s) absorbed | day-3 drift == day-1 drift = 2.0 s | ✅ no accumulation |
| Drift alerts fired | 0 | ✅ |
| Checkpoints written + MD5-verified | 3 / 3 | ✅ |
| PnL log lines, strictly monotonic on `cycle_ts` | 3 / 3 | ✅ |

The scheduler ticks against each day's **absolute** UTC target, so drift is
bounded by one sleep-chunk + wakeup latency and cannot accumulate across days.
Injected forward/backward clock jumps are absorbed within one chunk.

**Test B — crash + restart mid-cycle (crash-safe checkpoint — SURFACED FIRST): PASS**

| Assertion | Result |
|---|---|
| Crashed mid-cycle on day 3 (before checkpoint write) | ✅ |
| Latest checkpoint after crash = **day 2** (day 3 not written) | ✅ |
| Restart re-runs day 3 → checkpoint **byte-identical** to clean run | ✅ |
| Equity exact match (clean vs restart) | ✅ `100006.43 == 100006.43` |
| No duplicate PnL lines; strictly monotonic | ✅ (3 lines) |
| Day-3 checkpoint MD5-verified | ✅ |
| No orphaned tmp/lock files (atomic write) | ✅ `0` |
| Crash-window #2 (checkpoint written, log line lost) reconciled on boot | ✅ no gap, no dup |

The checkpoint is the **authoritative** record (written before the PnL line, and
carrying the exact `pnl_record`); on boot the runner reconciles the log against
it, so *neither* crash window (before-checkpoint / between-checkpoint-and-append)
can produce a missing or duplicated PnL line. Restart determinism holds because
the deterministic cycle is a pure function of `(prior checkpoint, cycle date)`.
