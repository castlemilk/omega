## §1 — What this is, and what it explicitly is NOT

**NOT a rehabilitation of the reasoning layer.** V241 measured per-cycle basket review on
the full 32-window walk-forward grid and refuted it — *"ACTIVE but adds variance, not
expectancy"* (recent mean-Δ +$226.56 vs a >+$400 bar; recent p25-Δ −$705.44 vs >+$500).
V258's specialist-ensemble rehabilitation was refuted at Phase 0 for $0 grid spend.
`reasoning_layer_enabled` stays `False` (`features.py:958`) and **V281 does not propose
turning it on.**

**IS a provider.** `reasoning_layer.py` can only talk to the `agy` CLI: `__init__` raises
on any `model_id` absent from `_AGY_MODEL_STRINGS` (`:44-48`), a closed dict of three
Gemini strings. There is no local-model path anywhere in the repo (`llm_shell.py` has no
ollama/vLLM/localhost hooks). This machine already runs `ollama` with
`qwen3.8:27b-mlx`, `qwen3:14b`, `gemma3:27b`.

**Why it is worth building even though the hypothesis is refuted.** V241/V258 were
shaped by their provider: V258's Phase 0 is labelled *"$0-grid, agy-wall-clock only"*,
and V240 notes the CLI *"exposes no temperature control, so live-call determinism is NOT
assumed."* A local provider removes all three constraints — free unlimited cache-fill
across all 32 windows, `temperature=0` + fixed `seed`, and a **separate `thinking`
field** the API returns alongside `response` (verified). None of that was available to
the refuted experiments. It makes future hypotheses cheap to test; it does not make the
dead ones alive.

## §2 — Design constraints (each forced by existing contracts)

1. **Subprocess, not in-process HTTP.** The V215 fence intercepts urllib/requests inside
   the run. V240 used an `agy` subprocess precisely because the fence *"does not and
   should not intercept"* it. The ollama provider therefore also calls out via
   subprocess. It is not a fence bypass: cache-miss under `OMEGA_FROZEN_CACHE=1` still
   **raises `LLMCacheMiss`**, so live calls happen only during explicit
   `OMEGA_LLM_CACHE_FILL=1` runs, and an LLM prompt is not market data.
2. **Cache namespace is `model_id`.** Each provider/model gets its own directory under
   `data/frozen_llm_cache/`, so the 693 committed `gemini-3.1-pro-low` entries are
   untouched and un-shadowed.
3. **The V241 posture is preserved unchanged.** `size_scale` stays clamped `[0, 1]` —
   trim or scale down only, never invent or up-size. The provider changes *who answers*,
   never *what the answer is allowed to do*.
4. **Thinking is captured, never trusted.** The trace is recorded for audit; the typed
   contract (`keep`/`drop`/`size_scale`) remains the only thing that can affect a
   position.

## §4 — Gates

| Gate | Assertion |
|---|---|
| **G1** (backwards compatibility) | Existing `agy` model ids still construct, still route to the agy path, and the committed `gemini-3.1-pro-low` cache still reads. A local model id constructs where it previously raised `ValueError`. |
| **G2** (hermetic contract preserved) | With `OMEGA_FROZEN_CACHE=1` and no cache entry, the ollama provider raises **`LLMCacheMiss`** — no live call, no neutral stub. This is the property the whole design rests on and it must hold per-provider, not just for agy. |
| **G3** (posture preserved) | A model returning `size_scale > 1.0` is still clamped to `1.0`, and `keep`/`drop` are still validated as subsets of the candidates. The provider cannot widen the layer's authority. |
| **G4** (end-to-end, live) | A real `qwen3.8:27b-mlx` call returns a parseable review, and its `thinking` trace is captured non-empty. Proves the provider works against the actual model, not a mock. |
| **G5** (standing path untouched) | The three sentinels reproduce **to the cent** — crisis $1,082.80 / trend $4,679.67 / recent $824.81 — with the flag OFF, which is the only configuration V281 ships. |

**Anti-Goodhart:** every gate is a correctness or reproduction gate. There is no PnL
number V281 can win, and none is reported.
