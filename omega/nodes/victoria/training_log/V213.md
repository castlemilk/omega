## Hypothesis

V212 proved (4-replicate audit + isolated diag) that enabling the V156
`strategy_selector` makes trend/crisis non-reproducible: 4 byte-identical-input
runs spanned **$18,720** (trend) / **$8,399** (crisis), and an isolated diag pair
diverged **$2,446** from identical state with the **same 81 trades**. Recent stays
deterministic ($0.66) but regresses −$583 (real, stands).

**Localization done this version (the V210-style cycle-1 bisect, but on the diag
artifacts already on disk — no new runs needed):**

- `data/v212_diag_trend_on_a_signal_contribs.jsonl` vs `_b` **differ at line 1**:
  the FIRST logged trade is at cycle 5 (run a) vs cycle 8 (run b), with different
  `sma_crossover` values (0.6033 vs 0.5263) and different `conviction`
  (SELL vs STRONG_SELL). The divergence reaches **signal computation itself**, not
  just downstream sizing.
- The selector reads `signals["_bull_prob"]/["_bear_prob"]` — **never written**
  anywhere (only `_regime_w_bull_prob/_bear_prob` exist) — so it always falls back
  to the discrete `_regime` **label** path. `_basket_breakout`/`_basket_mtf_alignment`
  are also never produced (always default 0.0). The selector's mode therefore
  switches purely on the regime **label** sequence + its window counters.
- The wasserstein regime detector is canonical (it builds its vector by iterating
  the fixed `SIGNAL_NAMES` list, not a dict), so a label flip can only come from a
  wobble in the `signal_values` it consumes.
- **Root cause:** `signal_generation.py:1149` builds `_cs_raw` by iterating
  `signals.items()` **unsorted**, then `_basket_mean = sum(_cs_vals)/len` (:1156).
  `signals` is populated in **async-completion order** on the parallel signal path
  (`victoria_node` `acc` accumulation), so the float-sum order — and thus
  `_basket_mean` — wobbles run-to-run by ~1e-12. Cross-sectional demeaning then
  subtracts `_basket_mean` from **every** composite. Selector-OFF the wobble stays
  below the trade-selection threshold (V211 trend floor $166). Selector-ON, the
  discrete regime-label counter is a hard threshold on a near-boundary value, so
  the wobble flips the label at some early cycle → the selector arms CRISIS/TREND a
  cycle off → mode-dependent weighting makes everything downstream diverge grossly
  (the 13% `sma_crossover` difference is the *consequence*, not the cause).

This is **the residual 4th channel V211 flagged** (the 105-vs-106 trend outlier):
V211 sorted `strategy.py`'s basket aggregations (`:1722` basket_std, `:2130`
basket_mean) but missed `signal_generation.py`'s **own copy** of the same
cross-sectional reduction.

**The V213 bet:** canonically sort the `signals.items()` reductions in
`signal_generation.py` (the V208a/V211 method) so `_basket_mean` is bit-identical
across runs → the regime label is deterministic → the selector arms at the same
cycle every run → trend/crisis spread collapses to < the V211 floor. Plus
defensive sorts on the selector-reachable `_apply_regime_signal_weights` path and
per-run disk-state isolation in the audit harness.

## Two-pronged fix (committed before the audit)

**A — canonical sort (the load-bearing fix per the localization above):**
- `signal_generation.py:1149` — `_cs_raw` now iterates `sorted(signals.items(), key=lambda kv: kv[0])` → `_basket_mean` reduction order-independent. **This is the primary fix.**
- `signal_generation.py:1181` — composite-spread log reduction sorted (consistency).
- `strategy.py:_apply_regime_signal_weights` (~:357) — outer `signals.items()` and inner `weights.items()` sorted; the `directional_vals` composite-recompute sum (~:371) sorted. This path is selector-reachable (fires when `regime_signal_weighting` is enabled with the selector) — defensive, since that flag is currently **undeclared** (a no-op the new banner surfaces).

**B — per-run state isolation (driver-level; no in-process singleton found):**
The selector carries no module-level mutable state (`_TREND/_CRISIS_OVERRIDES` are
read-only constants; the instance is created per `StrategyNode` per process). The
only cross-run vector is **disk state read at startup**. `signal_ic_history.json`
is empty (`{}`) at HEAD, and the three DBs are read-only under `--frozen-cache`,
so the cross-run channel V212 suspected is at most a near-ghost — but
`scripts/check_determinism.sh` snapshots all four and **restores them before each
replicate** so a cross-run channel cannot leak between runs. Per the parent brief:
ship A (load-bearing), implement B defensively, don't gate the launch on solving
the cross-run story.

## Conclusion

**Pre-registered hypothesis REFUTED on both branches; Fix A reverted.**

1. **The sort is not load-bearing.** The pre-reg said the basket_mean sort makes the
   regime label deterministic and collapses the selector spread. At the **canonical
   sleep=10**, ON-trend FAILS with *and* without the sort ($3,723 vs $3,430, both with
   the same 81↔83 entry flip). The sort makes no difference to the channel it was
   designed to fence.
2. **The sleep=0 "collapse" was a confound.** At sleep=0/3 the channel is dormant
   *regardless of the sort* (no-sort $75/$42 PASS). The apparent $18,720→$132 win was
   the sleep change (V212=10, audit=0), not the sort — exactly the cross-sleep trap
   the controls were run to check.
3. **The sort is actively harmful.** Pre-registered OFF falsifier fired and the
   pre-sort control **proved the sort caused it**: OFF-trend $89 (PASS) → $1,442
   (FAIL). The sort canonicalizes `_basket_mean` correctly in isolation but shifts the
   trade-selection baseline onto a *separate* latent channel (channel-2) that was
   dormant on the pre-sort baseline. Net effect on the production (OFF) path: a
   determinism regression.
4. **Decision: revert Fix A** (`23c9b3c`). Non-load-bearing + harmful = revert, per the
   pre-reg's own OFF falsifier. The defensive `_apply_regime_signal_weights` sorts went
   with it (they were predicated on the same wrong premise and sit behind an undeclared
   flag anyway).

**The real channel — relocalized.** It is a **sleep / wall-clock / async-timing**
dependency: dormant at sleep ≤3s, active at sleep=10, and it flips actual **entries**
(81↔83 trades, not just sizing). This matches V212's suspected "cross-run channel
(entry counts by sequence position)" but sharpens it: the trigger is the **per-cycle
sleep gap**, during which something time-dependent drifts (candidates: background WS
feed-manager threads, async signal accumulation order, or a signal that reads
wall-clock elapsed — the same wall-clock dependency the recent PnL level-shift hints
at). The basket_mean order was a red herring.

**What stands:**
- The two **observability deltas** (subsystem wiring banner + `check_determinism.sh`,
  now with a `--sleep` knob) — they are what *made* this refutation possible. The
  determinism checker's separate-process replicates + the sleep sweep localized the
  trigger in hours; the manual V207-V211 method would have taken versions.
- The wiring banner's incidental findings: `regime_signal_weighting` and `hmm_regime`
  are **undeclared no-ops**.
- The methodological lesson (now in the skill + backlog): **always measure determinism
  at the canonical eval condition (sleep=10), not a faster proxy** — sleep is a
  determinism variable here, not just wall-clock.

No high-water (V213 is a fence/diagnosis version and the selector is still not
evaluable). All V211 highs stand. README updated with the refutation + the sleep finding.
