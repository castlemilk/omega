## Why V207b exists

V207a pinned `PYTHONHASHSEED=42` and froze the funding cache. Two
expected outcomes:

- Crisis within-pair PnL spread collapsed **17×** ($1,978 → $113) —
  consistent with FP-summation noise being the dominant channel in
  crisis. ✅
- Recent + trend within-pair PnL spread got **vastly worse** —
  recent went +$0.08 → $3,257, trend went +$0.49 → $14,047 — and
  the trend trades.csv shows position sizes diverging by **exactly

  position management. ❌

The V206b noise floor on recent/trend was an artifact of the live
funding cache being **identical** across the two-minute gap between
r1 and r2 (cache freshness window > inter-run gap). With the cache
frozen, V207a is *more* deterministic in the obvious ways but a
**third channel** that was previously masked by the funding-cache
leak now dominates the metric.

V207b is **methodology-only — static analysis of existing V207a
artifacts.** No rerun. The prior V207b sketch planned a recent-pair

## Channel localization

The divergence is **downstream of the composite combiner** and
**upstream of `paper_trading.execute_proposals`** — i.e., somewhere
in `strategy.py:_construct_portfolio` between the per-symbol
composite (identical) and the final `weights` dict written into the
proposal.

The exact 2× ratio is the signature of a **clip-boundary
multiplier** in the sizing stack. The candidates in
`strategy.py:3143-3192` are:

```
raw_weights[ticker] = (
    w                              # base weight from composite ranking
    * conviction_size_multiplier(convictions[ticker])
    * _conv_scale                   # max(0.5, min(2.0, _w_conv / 0.25))  ← clip boundaries
    * _csb_long_mult / _csb_short_mult
    * _surf_conf                    # _surface_confidence per-candidate field
    * _cont_size_long_mult / _cont_size_short_mult  # V148 continuous regime
)
```

`_conv_scale = max(0.5, min(2.0, _w_conv / 0.25))` is the canonical
2× discontinuity: if `_w_conv` lands above 0.5, the clip returns 2.0;
if it lands at 0.25, the clip returns 1.0; ratio = 2.0 exactly.

`_w_conv` comes from `_compute_weighted_conviction()`
(`strategy.py:1024-1087`). When `live_signal_normalization=True`
(features flag), it z-scores each signal value against a **rolling
per-signal-name history** shared across symbols:

```python
hist = self._signal_history.setdefault(k, [])  # k is signal NAME, not (symbol, name)
hist.append(fv)
if len(hist) > _norm_window: del hist[0]
...
fv = (fv - _mean) / _std
```

The history is keyed on signal name only — so every symbol the
strategy considers in a given cycle mutates the same list, and the
mean/std at the moment any particular symbol is normalized depends
on **iteration order across symbols and across cycles**. A
non-traded symbol's signal value enters the history just as much as
a traded one; tiny noise in any single non-traded symbol propagates
into `_w_conv` for every later symbol in the same cycle.

This explains both observations simultaneously:

1. **Per-cycle composite_score drifts ~2e-4 from cycle 1** —
   _signal_history accumulates from cycle 1; even on cycle 1 the
   within-cycle iteration over candidates pushes values into hist
   in an order that can differ if any upstream ordering does.
2. **Per-trade signal_traces are identical** — signal_traces logs
   the raw signal values for the eventually-chosen ticker, not the
   z-scored `_w_conv` that drove the sizing decision.
3. **Exact 2× size at c34** — for ARBUSDT (trend), `_w_conv / 0.25`
   straddles 0.5 in one run and 1.0 in the other → `max(0.5, …)`
   clamps r2 at the 0.5 floor while r1 is just above it.

**Caveat:** confirming that `live_signal_normalization` *is* the
channel (vs. another stateful post-composite multiplier such as
`_surf_conf`, `_cont_size_*_mult`, `_fiedler_scale`,
`_geometry_size_mult`, or `_hv_size_mult`) requires a per-multiplier
instrumented rerun at cycle 34. The diagnostic profile (exact 2×,
clip boundary, first divergence late but pre-feedback) is most
consistent with `_conv_scale` driven by stateful normalization, but
other clip boundaries in the chain (`max(0.5, min(2.0, _boosted_conv / 0.25))`,
Fiedler clamp to `[0.25, 1.0]`) cannot be ruled out without
instrumentation.

## Conclusion

**The third noise channel is in `strategy.py:_construct_portfolio`'s
sizing-multiplier chain (lines 3143-3192), not in signal
computation.** All signal_traces, composites, and basket statistics
are byte-deterministic at trade time across runs. The divergence is
a 2× clip-boundary discontinuity, most likely originating in
`_compute_weighted_conviction`'s rolling z-score normalization
(`_signal_history` keyed on signal-name-only, mutated across all
symbols within and across cycles).
