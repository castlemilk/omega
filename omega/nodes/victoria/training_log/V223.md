## Hypothesis

V222 proved IC weighting is cleanly regime-conditional (both Δs common-mode —
the `_ic_weighted_composite` fsum fence cancels). The highest-EV, smallest-
surface next bet **banks the trend gain and removes the crisis loss**: gate the
IC-weighted conviction path on the cycle's **runtime regime label**. Apply seed
IC weights only where IC helps; fall back to the exact equal-weight raw
composite (bit-identical to the V222 IC-off control path) where it hurts.

**Bet:** regime conditioning preserves the trend IC gain while recovering the
crisis and recent losses, because recent's profit windfall lives in crisis
sub-cycles that will now bypass IC and re-capture the equal-weight selection.

## RESOLVED FORK — denylist on {crisis, high_vol}, NOT allowlist {trend,bull,normal}

The V223 brief said "use IC only in **trend/bull/normal**, bypass in
**crisis/high_vol**." The Explore + Plan agents refuted the *allowlist* wording
against the actual runtime label space:

- **`_cycle_regime_label` (strategy.py:1132,1136)** is `str(signals["_regime"]).lower()`.
  Its closed value set is **`{bull, bear, sideways, high_vol, crisis, default}`**
  (Wasserstein emits bull/bear/sideways `wasserstein_regime.py:66-70`; VRP maps
  FEAR→high_vol, COMPLACENCY→crisis `victoria_node.py:120-124`; macro forces
  sideways `:1299`; fallback `default` `:931`).
- **There is NO `trend` runtime label** — "trend"/"recent"/"crisis" in the
  results are **training SNAPSHOT names** (data periods), a different namespace.
- **`normal` is never directly emitted** — the code conflates it with `sideways`
  (`strategy.py:1769 _is_normal = _regime_consolidated in ("normal","sideways")`).
- The per-regime IC table (`data/signal_ic_history.json → seeded_regime_ics`) is
  keyed on exactly **`normal` / `crisis` / `high_vol`** — no `trend`/`bull` keys.

An **allowlist** of `{trend, bull, normal}` would bypass IC for every
`sideways` / `bear` / `default` / `unknown` cycle — i.e. the bulk of
trend-snapshot trading — silently discarding V222's proven +$3,331 trend gain.
**The faithful implementation of the brief's intent ("IC-off in crisis/high_vol")
is a denylist:**

- **IC-OFF (bypass → equal-weight raw composite):** `crisis`, `high_vol`
- **IC-ON (use IC weights):** everything else — `normal`, `sideways`, `bull`,
  `bear`, `default`, `unknown`, `""`.

Gate keys on the **runtime `_regime` label**, never the snapshot name.

## PRE-GRID FINDING (2026-06-14, smoke + 200-cycle regime probe) — snapshot ≠ runtime regime

The shipped per-cycle IC-gate tally immediately earned its keep. A 5-cycle smoke
showed `ic_off_cycles=0` on **every** snapshot — the gate never fired. Root
cause: the Wasserstein regime detector (`window=50, min_samples=20`) needs ~tens
of cycles to warm up; the VRP→FEAR/COMPLACENCY mapping (the only path to
`high_vol`/`crisis`) is also degraded under frozen-cache (FearGreed/VRP HTTP
blocked). A 200-cycle regime probe (`--sleep 0`, regime is sleep-independent) on
each snapshot gives the real runtime `_regime` distribution:

| Snapshot | normal | high_vol | crisis | IC-ON cyc | BYPASS cyc | BYPASS % |
|----------|-------:|---------:|-------:|----------:|-----------:|---------:|
| crisis | 121 | 39 | 40 | 121 | **79**  | 40% |
| trend  | 103 | 38 | 59 | 103 | **97**  | 48% |
| recent |  87 | 29 | 84 |  87 | **113** | 57% |

**The runtime regime label does NOT track the snapshot name.** Each training
snapshot is a *mix* of runtime regimes. The "trend" snapshot (a 2023-Q4 price
period) is itself ~48% crisis/high_vol at runtime; "recent" is ~57%. So V223's
gate does **not** implement "trend-snapshot→IC-on, crisis-snapshot→IC-off" — it
implements **true per-cycle regime conditioning**: equal-weight on every
crisis/high_vol-labeled cycle, IC-weights on every normal-labeled cycle, *within
each snapshot.* This is a more principled instrument than the brief assumed, but
it means the per-gate Δ is **no longer predictable from V222's snapshot-level
deltas.** The smoke confirmation (`[V223] IC-gate summary` line, visible) is the
200-cycle counts above, NOT the warmup-blind 5-cycle counts.

## Conclusion

**V223 is NOT a high-water.** The regime gate is a genuine, deterministic
improvement *over always-on IC* (Pareto-superior: +$161 trend, +$470 crisis,
+$1,854 recent, all bit-stable). But the decisive comparison is against the
standing incumbent — **V221-era equal-weight (IC-off)** — and there V223 **loses
net by $1,862** (+$1,153 IC-off vs −$709 V223). IC weighting, even regime-gated,
is net-negative versus simply not using it.

The result sharpens the IC verdict to a single sentence: **the pooled seed ICs
have a real, large edge in trend cycles (+$3.5k vs equal-weight) and are
net-harmful everywhere else, and gating by runtime regime cannot fix the harm
because the damage lives in the *normal*-labeled cycles the denylist leaves IC-on
(most visibly the crisis snapshot, where 121 IC-on cycles drive a −$7.8k loss).**
IC has now been refuted twice against equal-weight — V222 always-on (net −$3.2k)
and V223 gated (net −$0.7k), both below IC-off +$1.2k. The open question is no
longer *where* to apply the ICs (gating answered that) but *whether the ICs
themselves are correct* — and we have only ever used **pooled seed defaults**,
never data-derived per-(regime, signal) estimates.

**Standing main remains V221-era equal-weight (IC-off).** The
`regime_conditional_ic_weighting` flag stays committed but **defaults OFF** — it
is the correct *structure* for IC and net-better than always-on, so it is the
harness to keep if IC is ever rehabilitated; it is not promoted to main.
