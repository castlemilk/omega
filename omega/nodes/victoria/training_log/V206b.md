## Why V206b exists

REFLECTION_V205.md (committed `9fb04f1`) found two facts that block any
further strategy edits:

1. The V172 "architecture stack" V204 restored is **code-present but
   runtime-inert** under `v93_baseline`: `strategy_selector_enabled`,
   `regime_signal_weighting`, `per_regime_ic_weighting`,
   `live_signal_normalization` all default `False` and are not set
   by any preset, config, or training script. The "V156 strategy_selector
   initialised" INFO line is absent from V204 and V205 logs.
2. Despite (1), V205's pre-registered no-op edit
   (`_REGIME_SIGNAL_WEIGHTS["CRISIS"] = {}` — a dict that is never read
   under v93_baseline) moved crisis PnL by +$14,277σ vs V204. The
   eval has hidden state coupling and we have been reading dict-edit
   noise as architectural signal for six versions (V199–V205).

V206b's job is **not** to fix the leak. Its job is to **locate** it.
Until we know what couples runs together, every PnL delta we measure
is contaminated by that coupling at unknown amplitude.

## Hypothesis

**Identical `strategy.py` + identical `--seed 42` + identical
`--backtest-snapshot` should produce byte-identical artifacts across
two sequential runs.** Any artifact that differs locates a state-leak
channel.

Artifacts in scope (whichever exist after a real run):

- `data/v206b_<gate>_<run>_results.json`
- `data/v206b_<gate>_<run>_trades.csv`
- `/tmp/v206b_<gate>_<run>_metrics.jsonl`
- `data/omega_victoria_state.db` (244K, sqlite — likely accumulates)
- `data/omega_victoria_memory.db` (76K, sqlite — likely accumulates)
- `data/decision_traces/<...>.jsonl` if `DecisionWriter` is wired for this version

The persistent sqlite DBs are the most suspicious channel:
`run_training.py:195` uses `data_dir / "omega_victoria_memory.db"`
and the file is 76K *now*, before V206b runs — meaning prior training
runs have left content there. If `StrategyNode.__init__` reads from
that file, the second run starts from a different state than the
first.

## Procedure

For each gate ∈ {recent, trend, crisis}:

1. Record a pre-run fingerprint of the persistent state:
   `sha256sum data/omega_victoria_state.db data/omega_victoria_memory.db`.
2. Run #1:
   ```
   python3 scripts/run_training.py \
     --version v206b_<gate>_r1 \
     --cycles 200 --sleep 10 --seed 42 \
     --backtest-snapshot data/snapshots/<snap>.json
   ```
3. Snapshot artifacts and the post-run sqlite files into
   `data/v206b_audit/<gate>_r1/`.
4. Run #2: same command with `--version v206b_<gate>_r2`. Same seed.
   Same snapshot. Identical strategy.py (no edits between runs).
5. Snapshot artifacts and sqlite files into
   `data/v206b_audit/<gate>_r2/`.

Snapshot file mapping (per V204/V205 logs):
- recent → `data/snapshots/snap_20260414.json`
- trend → `data/snapshots/snap_trending_2023q4.json`
- crisis → `data/snapshots/snap_crisis_2022h1.json`

All six runs are sequential — never overlapping — because parallel
runs would contaminate the shared sqlite DBs and obscure exactly the
signal we're trying to measure.

## Falsifiers (operational)

A divergence is **real** if:

- `cmp -s` returns non-zero between r1 and r2 of the same gate for
  the same artifact, AND
- For trades.csv specifically: the 5 spot-checked rows at the same
  `(cycle, symbol, side)` keys show different `pnl` values.

A divergence is **not real** if it only appears in timestamp fields
that are *purely* observational (e.g. `run.date`, `elapsed_s`,
`avg_cycle_s` in `results.json`). Those are wallclock artifacts and
do not constitute a state leak — they just need to be excluded from
the comparison.

## Conclusion

### Most likely coupling mechanism

**Two compounding, independent channels:**

1. **`PYTHONHASHSEED` is unset** in `scripts/run_training.py` (only `random.seed(42)` and `np.random.seed(42)` are set at line 486-487). CPython randomizes the string-hash seed per process, which permutes the iteration order of any `set` or string-keyed dict in the signal composite. Floating-point summation in a permuted order produces O(1e-4) drift in the composite score from cycle 1 — exactly what `metrics.jsonl` shows. **This explains the recent/trend within-pair drift (sub-dollar, decisions stable) and the crisis trade-set bifurcation (1e-4 perturbations cross tight conviction thresholds).**

2. **`data/macro_cache.db::funding_rate_cache`** is fetched live and rewritten at every run start. Run #2 reads rates that run #1 fetched. This is the obvious candidate for the V204→V206b $8k trend drift (V204 ran days ago with then-current funding rates; V206b r1 ran today with freshly-cached rates). Per-pair drift within V206b is small because r1 and r2 sit minutes apart on the same wallclock surface, but cross-day drift compounds.

The combined mechanism: process-hash-seed flips iteration order of an internal dict/set, which produces a ~1e-4 composite bias; the bias compounds linearly through equity-dependent sizing in stable regimes (recent, trend) and triggers conviction-threshold crossings in unstable regimes (crisis). Funding-rate cache mutation adds a second, slower drift component visible only across runs that don't share a quote window.

### Status of V204 and V205 numbers

- **V204 trend +$22,105 — REJECTED.** Same strategy.py on the same snapshot today produces +$13,993 (n=78, repro within $0.49 across pair). Net delta vs V204 = −$8,112 with no code change. The +$22,105 trend "high-water" is not stable across days and should be struck from the README high-water table.
- **V205 crisis −$8,533 — REJECTED as a high-water break.** Within-pair noise on the V206b crisis no-op is **$1,978** (r1=−$22,959 / r2=−$24,937). The V204→V205 claimed swing of +$14,277 is ~7× the within-pair noise of a literal no-op on the same code — large but not implausibly large given the conviction-threshold bifurcation pattern. The cleaner read is "V204 crisis ≈ V206b crisis ≈ −$23k ± $2k; V205's −$8,533 is an outlier that has not been re-observed." Re-running V205's exact code is the only way to discriminate confidently, but on the noise floor we've now measured the +$14,277 claim cannot be defended as signal.
- **V206b r1 crisis = −$22,959 reproduces V204 within $150.** This is the closest pairing the data offers. The V204 ceiling is therefore *probably* a real point but with σ ≥ $1,978; treat **−$23k ± $2k** as the crisis noise envelope going forward.

### Per-artifact diff summary (one-line)

- **DBs (state.db / memory.db / victoria_state.db):** identical across all six runs. Not the leak.
- **results.json:** diverges in `version`, `run.date`, `elapsed_s`, `avg_cycle_s` (cosmetic) + `performance.total_pnl_usd` and counts (substantive — locates the leak in trade outcomes, not in summarization).

- **metrics.jsonl:** `composite_score` diverges by ~1e-4 from **cycle 1**, before any trade. Stable per-process bias. This is the proximal observable.
- **decisions.jsonl:** diverges (downstream of metrics).
