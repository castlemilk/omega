## 1. Mechanism under test (no code changes)

`run_training.py:1105` gates the ONLY populate path for both `_signal_ics` and
`_regime_ics`:

```python
if _strat is not None and bool(getattr(_active_features, "ic_seed_weighting", False)):
    ...
    _strat.update_signal_ics(_seed_pooled)     # line 1152
    _strat.update_regime_ics(_seed_regime)     # line 1154
```

With `ic_seed_weighting=False` both dicts stay empty ⇒ in
`_compute_weighted_conviction` every `ic = self._signal_ics.get(k, 0.0)` is `0.0`,
every term is skipped by the `abs(ic) < 1e-4` continue, `total_ic == 0.0`, and
`strategy.py:1241` returns the **raw equal-weight composite**. `per_regime_ic_weighting`
is therefore **doubly inert** when `ic_seed_weighting=False`: its `_regime_ics`
lookup is guarded by `if _per_regime and self._regime_ics`, and `_regime_ics` can
only be populated inside the same gated block.

So the flag pair collapses to a single binary arm, and the IC-OFF arm is exactly the
equal-weight path. **Bounded scope honored:** V274 changes NO code. The only lever is
the `--features` JSON handed to `scripts/run_training.py`. `strategy.py`,
`omega/nodes/victoria/*`, and the walk-forward machinery are not touched.

## 8. Conclusion

**The standing baseline survives, because it never carried the defect.** V273's H3
named a real defect class — `ic_seed_weighting` / `per_regime_ic_weighting` default
ON, feeding retrospectively win-rate-derived ICs into a pure entry gate — but its §7
extension of that finding to the standing baseline was an inference from flag
defaults, and the run record refutes it: all 32 windows behind crisis +$599 / trend
+$2,997 / recent +$30 ran `ic_seed_weighting: false`, reproduce to the cent, and
re-run today at 0.000000 drift. Every V### that gated on "must not move the standing
baseline" was measuring against a number whose entry gate was equal-weight, not
IC-weighted. **The measuring stick is clean.**

**What the campaign avoided was not small.** With the overlay on, all 32 cells move,
31 change trade count, 8 flip sign, and one crisis window swings 7×. The IC-OFF
convention that every walk-forward grid script has carried since V226 was therefore
load-bearing at the cell level — not a stylistic default. That it nets to inside the
MDE in all three families and pooled does **not** make it harmless; it makes it
*undirected*, which is the worse property for a knob that was on by default in the
code and off only by the convention of whoever wrote each grid script.

**G1 fails as written and the finding does not turn on it.** Trend's +29.8% breaches
the pre-registered ±20% band; crisis (+13.1%) and recent (−18.8%) do not. But all
three bands sit below the instrument's own MDE, which §2 stated before any number
existed, so the pattern — every family inside its MDE, every cell moved — carries the
information and no single family's rel-Δ does. Reading trend's FAIL as "IC weighting
improves trend by $892" would be exactly the inference V247 forbids.

**No follow-up is queued.** Per §5 this version does not fish for a partial-IC
variant, and the result gives no reason to: the overlay is a heavy-coupling knob that
is unmeasurable on this manifest and whose per-cell footprint is pure variance. The
correct standing action is the one already in force — leave it off — plus the two
housekeeping items below.
