## Do Prediction Markets Forecast Cryptocurrency Volatility? (Kalshi Macro Contracts)
**Source:** arXiv 2604.01431 (Mohanty et al., 2026-04-01) — https://arxiv.org/abs/2604.01431
**Type:** paper
**Score:** 4/5 × 4/5 = 16/25 — **Queue**

**Summary:** Daily probability changes on Kalshi macro contracts (KXFED rate path, KXRECSSNBER recession risk, KXCPI inflation) predict realized volatility for BTC/ETH/SOL/ADA/LINK out-of-sample, beating Fed Funds futures, Treasury yields, and the Deribit DVOL index. Bitcoin volatility is best predicted by the recession-risk channel (MSFE ratio 0.979, p=0.020); altcoin volatility loads on the inflation channel (ETH MSFE 0.959, p=0.010). Sample: Jan 2023 – Mar 2026.

**Gap analysis:**
- Does Omega do this? **No.** Omega has Fear & Greed and funding rate but no prediction-market data or macro-event probabilities. Closest existing signal is the Bayesian regime detector, which runs purely on returns.
- What would change: New signal node `prediction_market_macro` under `omega/nodes/victoria/` that polls Kalshi contracts and emits per-cycle probability deltas as a volatility-forecast feature into the meta-ensemble. Could feed both the conviction filter (raise long thresholds when recession-risk Δp > 0) and a new vol-targeted sizing path.
- Dependencies: Kalshi public API (free, REST, daily settlement series available without an account). No new ML — paper uses linear regressions. Adds ~3 features.

**Recommendation:** Queue for next signal sprint. Concrete steps: (1) build `omega/nodes/victoria/kalshi_macro.py` polling KXFED/KXRECSSNBER/KXCPI daily; (2) add to `signal_generation.py` as a low-frequency feature (forward-fill intraday); (3) wire into `meta_learner.py` ensemble with IC weighting; (4) add a regime-conditional gate in `_apply_regime_adaptive_thresholds` — if recession-risk Δp > +0.02 over 3 days, multiply long thresholds by 1.25. Worth running an offline IC study first against existing v139 trade log before integrating live. The headline t-stats are strong but post-pub IC decay is real for macro signals.

## Meta-RL-Crypto: Self-Improving Transformer Agent for Crypto Returns
**Source:** arXiv 2509.09751 (Wang et al., revised 2026) — https://arxiv.org/html/2509.09751
**Type:** paper
**Score:** 3/5 × 1/5 = 3/25 — **Skip**

**Summary:** Unified transformer that cycles a single LLM through actor/judge/meta-judge roles to self-improve a crypto trading policy with no human supervision. Inputs are multimodal: on-chain activity, news, social sentiment. Claims to outperform LLM-based baselines on "technical indicators of the real market" — abstract is vague on numerical performance.

**Gap analysis:**
- Does Omega do this? **No**, but the architecture is far from Omega's current shape. Omega's meta-controller is a logistic ensemble plus an LLM regime annotator, not an end-to-end RL agent.
- What would change: Would require a full RL training stack, GPU infra, and replacing or paralleling the current meta-learner. Multi-week effort with unclear edge over the existing Sharpe 1.82 baseline.
- Dependencies: GPU training, an LLM fine-tuning pipeline, substantially more historical data than Omega currently retains.

**Recommendation:** Skip. Performance numbers are not concrete in the abstract, the engineering cost is large, and self-improving LLM agents in finance have a poor track record of out-of-sample stability. Revisit only if the authors release code with reproducible Sharpe figures on a public benchmark.
